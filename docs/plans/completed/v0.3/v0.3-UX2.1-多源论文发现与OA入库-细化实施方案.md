# Conflux-Weave v0.3 UX2.1 多源论文发现与 OA 入库细化实施方案

## 1. 文档状态

- 方案：B（OpenAlex + arXiv + Open Access 全文落地）
- 状态：`implemented_live_validated_bounded`
- 上游：`v0.3-UX2-资料库工作台-功能计划.md` 阶段二
- 本文用途：冻结论文发现、去重、全文获取、解析和入库的产品范围与验收边界

本文同时记录本阶段已经实现的范围、真实来源验收证据和仍受外部条件限制的边界。

## 2. 背景与问题

当前资料库已经提供论文搜索与获取入口，但论文能力仍以 arXiv 为中心：

- 学科覆盖有限，期刊论文和跨学科结果容易漏检；
- 中文主题依赖查询改写后再搜索 arXiv，搜索质量受单一来源限制；
- 搜索结果、下载地址和入库身份都与 arXiv ID 绑定；
- 下载只覆盖 arXiv 地址，缺少通用的合法开放全文发现；
- 搜索、下载、解析和知识库可用状态没有充分区分；
- 同一论文的预印本、正式发表版本和多来源记录缺少统一合并机制。

本阶段将论文获取从“单一站点搜索和下载”升级为“多源论文发现、开放全文解析与可追踪入库”。

## 3. 目标

### 3.1 核心目标

1. 使用 OpenAlex 作为跨学科主发现源，arXiv 作为预印本和计算机、人工智能、数学等领域的补充源。
2. 用统一论文记录承载 DOI、arXiv ID、OpenAlex ID、来源、版本和开放全文地址。
3. 将多来源中的同一论文合并，避免重复展示、重复下载和重复入库。
4. 建立合法 OA 全文获取链，找不到全文时仍保留元数据。
5. 明确区分发现、下载、解析和知识库可用状态，失败可见、可解释、可重试。
6. 保留每次外部检索与下载的来源、时间、实际查询、响应状态和最终落地结果。

### 3.2 用户结果

用户在资料库中输入中文或英文主题后，应当能够：

- 看到来自 OpenAlex 和 arXiv 的合并结果；
- 了解每篇论文来自哪里、为什么被检索到、是否存在开放全文；
- 区分预印本和正式发表版本；
- 选择只保存论文信息，或获取全文并入库；
- 在部分来源失败时继续使用其他来源结果；
- 查看下载或解析失败的原因并执行恢复操作。

## 4. 非目标

本阶段明确不做：

- 不爬取 Google Scholar HTML 页面；
- 不接入 Sci-Hub 或其他版权边界不明确的下载渠道；
- 不把论文获取自动变成研究报告或对话；
- 不在首批引入 Celery、Redis 或分布式任务集群；
- 不在首批接入 Semantic Scholar、Europe PMC 等全部来源；
- 不在首批强制部署 GROBID；
- 不用引用数替代相关性，也不声称搜索结果代表论文质量；
- 不修改深度研究默认使用网络与当前知识库的既定模式。

## 5. 总体功能链路

```text
用户主题或筛选条件
        ↓
查询理解与来源查询生成
        ↓
OpenAlex + arXiv 独立检索
        ↓
统一论文记录、跨源去重与版本关联
        ↓
相关性排序和来源状态展示
        ↓
保存元数据 / 获取开放全文
        ↓
OA 地址解析与下载验证
        ↓
PDF 解析质量检查
        ↓
资料库登记
        ↓
用户选择是否加入当前知识库
```

任何单一来源失败都不应抹掉其他来源已经取得的结果。下载失败也不应删除已保存的论文元数据。

## 6. 统一论文记录

### 6.1 基本信息

每篇候选论文统一记录：

- 标题、作者、摘要、发表年份；
- 期刊、会议或预印本来源；
- DOI、arXiv ID、OpenAlex ID；
- 学科主题和来源分类；
- 原始落地页和可用 PDF 地址；
- 是否开放获取及其判断来源；
- 元数据更新时间和各来源获取时间。

### 6.2 身份与版本

- 系统生成来源无关的论文身份，不再把 arXiv ID 当作唯一业务主键；
- DOI 相同的记录视为同一正式论文；
- arXiv ID 相同的记录视为同一预印本；
- 标题、年份和主要作者高度一致时标记为待合并候选；
- 预印本与正式发表版本建立版本关系，不静默覆盖；
- 无法确定是否相同时宁可保留两条并提示用户，不进行不可逆误合并。

## 7. 多源论文发现

### 7.1 查询输入

支持：

- 中文或英文研究主题；
- 精确标题；
- DOI 或 arXiv ID；
- 可选年份范围；
- 可选来源、学科和 OA 条件；
- 可选结果数量与排序方式。

### 7.2 查询理解

中文主题先形成结构化检索意图，包括核心概念、英文术语、同义表达和可选领域约束，再生成各来源适用的查询。查询理解失败时显示明确原因，不以空结果伪装成功。

精确 DOI、arXiv ID 和英文标题采用确定性路径，避免不必要的模型改写。

### 7.3 OpenAlex

OpenAlex 作为默认跨学科来源，负责：

- 主题、标题、作者和出版物检索；
- 年份、学科、期刊和 OA 条件筛选；
- DOI、正式出版信息和主题信息补全；
- 提供公开可用的最佳 OA 落地地址。

### 7.4 arXiv

arXiv 继续负责：

- AI、计算机、数学、物理等领域预印本发现；
- arXiv 分类筛选；
- 预印本版本和更新时间；
- 官方 PDF 地址。

现有缓存、限流、有限重试和来源响应留存继续沿用。

### 7.5 部分成功

搜索响应分别记录每个来源的：

- 实际查询表达式；
- 成功、无结果、限流、超时或失败状态；
- 原始命中数量和合并后贡献数量；
- 是否使用缓存；
- 可执行的恢复建议。

一个来源失败而另一个来源成功时，整次搜索状态为“部分完成”，结果仍可浏览和入库。

## 8. 去重、版本关联与排序

### 8.1 去重优先级

1. DOI 完全一致；
2. arXiv ID 完全一致；
3.其他可靠来源标识一致；
4. 规范化标题、年份和主要作者组合一致；
5. 标题高度相似但版本信息不同的记录只建立候选关系，不自动合并。

### 8.2 合并原则

- 保留所有来源及其原始字段；
- 对冲突字段记录来源差异，不静默选择错误值；
- 优先展示正式出版信息，同时保留预印本入口；
- OA 地址可以来自不同来源，但必须记录提供者和最终下载地址。

### 8.3 排序

默认排序综合：

- 标题与摘要的主题匹配；
- 学科和主题一致性；
- 查询中的必要概念覆盖；
- 发表时间；
- 引用影响力；
- 是否有合法开放全文。

用户可切换相关性优先、最新优先和高影响优先。引用数仅作为辅助信号，避免压制新论文。

## 9. OA 全文获取

### 9.1 获取顺序

1. arXiv 官方 PDF；
2. OpenAlex 提供的最佳 OA 地址；
3. 通过 DOI 请求 Unpaywall，寻找合法公开副本；
4. 后续阶段允许增加其他已审核的 OA 来源；
5. 用户自行配置的机构访问方式作为独立可选能力，不默认启用。

### 9.2 下载验证

每个候选地址都需要记录并检查：

- 请求状态和重定向结果；
- 最终域名和最终 URL；
- 响应是否确为 PDF；
- 文件大小是否合理；
- 文件是否完整且能够打开；
- 下载时间、来源和失败原因。

只有通过文件验证后才进入解析阶段。一个地址失败时可以尝试下一个合法候选地址，但每次尝试都必须保留记录。

### 9.3 无全文情况

没有 OA 全文时：

- 论文仍可作为“仅元数据”保存；
- 显示未找到合法开放全文；
- 保留 DOI、落地页和已尝试来源；
- 不把付费墙页面、HTML 错误页或登录页面保存为 PDF；
- 不将“仅元数据”标记为解析完成或知识库可用。

## 10. 处理状态与恢复

### 10.1 论文状态

- `discovered`：已发现候选；
- `metadata_saved`：元数据已保存；
- `oa_unavailable`：未找到合法开放全文；
- `fetch_queued`：等待获取全文；
- `fetching`：正在获取；
- `fetch_failed`：获取失败；
- `downloaded`：全文已验证并保存；
- `parsing`：正在解析；
- `parse_failed`：解析失败或质量不足；
- `parsed`：正文解析合格；
- `knowledge_ready`：已经加入当前知识库并可检索。

资料登记、正文解析和知识库可用是三个不同事实，界面不得用一个“处理完成”替代。

### 10.2 恢复动作

- 来源限流或超时：稍后重试对应来源；
- 无 OA 全文：保留元数据，允许以后重新解析 OA 地址；
- 下载失败：查看候选地址和失败原因，重新获取；
- 解析失败：保留原始 PDF，重新解析或更换解析方式；
- 已存在：打开现有资料或关联新版本，不重复写入。

## 11. PDF 解析质量

首批继续使用现有轻量 PDF 解析能力，但必须增加最低质量判断：

- 是否提取到有效正文；
- 有效文本页数和总页数；
- 提取字符数；
- 是否存在明显乱码或异常重复；
- 是否能够形成可定位正文片段。

零正文或明显不可用的文本必须标记为 `parse_failed`，不能标记为 `parsed`。

GROBID 作为后续可选增强，用于章节、作者、摘要、参考文献和文内引文结构化。未部署 GROBID 时基础流程仍应可用。

## 12. 资料库界面

### 12.1 搜索区

提供：

- 主题或标识符输入；
- 年份范围；
- 来源筛选；
- 学科筛选；
- 仅看 OA；
- 结果数量；
- 排序方式。

### 12.2 搜索状态

展示：

- OpenAlex 和 arXiv 各自状态；
- 查询理解状态和实际检索表达式；
- 原始结果数、去重数和最终结果数；
- 部分完成、限流或失败原因。

### 12.3 结果项

每条结果展示：

- 标题、作者、年份和出版物；
- 来源标签与版本关系；
- 摘要；
- OA 状态；
- DOI、arXiv ID 等标识；
- “保存元数据”“获取全文并入库”“打开来源”操作；
- 已存在、正在处理或失败状态。

## 14. 验收标准

### 14.1 批次一

- “地理智能体”“灾害知识图谱”等中文主题能够实际查询 OpenAlex 与 arXiv；
- 英文主题、精确标题、DOI 和 arXiv ID 有明确检索路径；
- 任一来源失败时，其他来源结果仍可显示；
- 用户能看到来源状态、实际查询和部分完成说明；
- 同 DOI 或同 arXiv ID 的记录不重复展示；
- 不改变论文获取不自动生成研究报告的产品边界。

### 14.2 批次二

- arXiv、OpenAlex OA 和 Unpaywall 候选地址按顺序工作；
- 下载到 HTML、登录页或损坏文件时不会标记成功；
- 同一论文不会因来源不同重复下载和入库；
- 找不到全文时可以保存元数据；
- 每次地址尝试和最终结果可追踪。

### 14.3 批次三

- 下载成功、解析成功和知识库可用分别展示；
- 零正文 PDF 不会显示为解析完成；
- 下载或解析失败保留原始记录和明确恢复动作；
- 解析成功的正文可在资料详情中预览和搜索。

### 14.4 搜索质量验收

实施前冻结一组包含以下类型的代表性查询：

- 中文研究主题；
- 英文研究主题；
- 跨学科主题；
- 新兴术语；
- 精确标题；
- DOI 与 arXiv ID；
- 合理无答案案例。

由人工标注前十结果中的相关论文和明显误匹配。优化以相关结果覆盖、明显误匹配、重复结果、来源失败率和全文落地成功率为依据，不以单个查询成功代替整体可用性验收。

## 15. 风险与控制

### 15.1 外部来源限流

各来源独立限速、缓存和记录健康状态。Semantic Scholar 在匿名条件下易限流，因此不进入首批主链路。

### 15.2 错误合并

强标识符优先自动合并；模糊标题只建立候选关系。所有来源字段保留，不做不可追踪覆盖。

### 15.3 OA 地址不稳定

不信任元数据中的 URL 即代表可下载 PDF。必须经过实际响应与文件验证，并保留最终地址。

### 15.4 解析质量不足

解析成功必须有质量依据。复杂版式、扫描件和数学公式属于已知限制，后续由 GROBID 或 OCR 路线增强。

### 15.5 范围膨胀

首批只做 OpenAlex、arXiv 和统一身份。没有完成批次一验收前，不并行扩展 S2、Europe PMC、GROBID 或分布式队列。

## 16. 回滚与停止条件

### 16.1 回滚

- 新多源搜索作为资料库论文获取的独立路径接入；
- 原有 arXiv 适配器和来源可靠性能力继续保留；
- 新来源出现严重故障时可以单独停用，不影响本地资料和现有 arXiv 能力；
- 新统一论文记录不得破坏历史资料的文档 ID、来源快照和引用定位。

### 16.2 停止条件

出现以下情况时暂停扩大实现范围并报告：

- 统一身份设计会破坏已有引用或历史资料版本；
- OpenAlex 的许可、限流或必要配置无法满足本地工作台使用；
- 跨源自动合并无法达到可审计和可回退要求；
- 外部 API 真实结果无法支持既定代表性查询；
- 需要引入新的长期后台基础设施才能继续。

## 17. 实施入口

方案批准后从批次一开始：先冻结统一论文记录、来源状态和搜索评估样例，再接入 OpenAlex 与现有 arXiv 聚合。批次一通过真实双来源查询和界面验收后，才进入 OA 下载与入库批次。
