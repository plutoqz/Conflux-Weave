# Conflux-Weave v0.3 W1.5 回答质量升级（多查询检索 + 知识分层报告）细化实施方案

## 1. 问题与定位

W1 之后报告结构达标，但内容密度不足。同一问题（"智能体的 skill 是怎么发挥作用的？"），
对照 Gemini 级回答，瓶颈在三个闸门：

1. 单 Agent 只做 1 次检索、取 top-8 页级片段、每段截断 2400 字符 → 证据供给太薄；
2. Claim 抽取上限 5 条 → 写作原料太少；
3. Writer 只能复述已核验 Claim，没有任何模型知识补充通道 → 语料没覆盖的部分报告无法解释。

W1.5 在不破坏 evidence-bound 审计语义的前提下打开这三个闸门。依据是设计文档 v0.3
第 41 行："综合网络信息、用户知识库和模型知识，回答深度研究问题，标注引用、证据范围和
可信度"——模型知识本来就是规划内来源，交付合同里也预留了 `○ 一般背景` 标记。

本文件部分取代 W1 方案第 2.2 节（Writer 根键从 3 个变 4 个）。

## 2. 杠杆一：多查询检索（单 Agent 路径）

- 新增查询规划调用（`s1-research-plan-queries`，temp 0，800 tokens）：输入 objective，
  输出 `{"queries":["…"]}`（1–4 条、非空、每条 ≤200 字符）；objective 本身恒为第一条，
  去重后截断到 4 条。
- 每条查询独立执行 Hybrid 检索（各 1 次 embedding + 1 次 rerank），按 chunk 去重
  （保留最高分）后按分数排序，合并取前 **16** 条作为 Evidence 池；引文截断
  2400 → **3600** 字符。
- 检索工件 schema 升级为 `conflux-weave.retrieval-tool-result.v2`（含 queries、
  每查询运行明细、合并结果）。
- `VerifiedResearchWorkflow.execute` 新增 `max_queries` 参数，**默认 1（行为不变）**；
  durable 单 Agent 适配层传 4，Manager 子运行传 1（其预算公式 `2+6N` 因此保持不变）。

## 3. 杠杆二：Claim 预算

- 草稿/修复 prompt 上限 5 → **10** 条；解析器硬上限 12 条（超出即 ValueError，维持
  现有 fail-closed 语义）；draft/repair max_output_tokens 1800 → **4096**。
- 验证器、修复轮次（1 轮）、citation closure 全部不变。

## 4. 杠杆三：知识分层报告（cited lane + background lane）

Writer 输出根键变为 4 个：
`{"summary":{…}, "sections":[…], "background":[{"heading","text"}], "open_questions":[…]}`

- **cited lane**（summary + sections）：与 W1 完全一致，逐段 claim_ids 闭合 + 独立审计，
  段末 `[n]` 引用。
- **background lane**（background，0–6 项，heading ≤200 字符、text ≤4000 字符）：
  模型知识补充，用于语料未覆盖的概念背景、术语解释、通用机制与典型流程。边界由
  **结构性隔离**保证（不依赖 prompt 单独保证）：
  - 不携带 claim_ids、不进入 Claim/Evidence/Citation 台账、不参与 C3 覆盖率；
  - 不做 faithfulness 审计（审计只覆盖 cited 段落）；
  - 渲染在独立章节「背景补充（模型知识 · 未经证据核验）」，每项带 `○` 标记
    （与 v1 图例"○ 一般背景"一致）；
  - prompt 约束：只允许概念性解释，不得包含具体统计数字、日期、价格等易错事实，
    不得与 cited 内容矛盾——此为可读性约束，真正的边界是上面的结构隔离与标注。
- 结构化 Artifact schema 升级 `conflux-weave.research-report-document.v3`；
  报告 Markdown schema 仍为 `…-report.v2`（交付物消费方不受影响）。
- Writer prompt 同时给出质量基线：摘要 2–5 句直接回答；按机制/主题分 2–6 节，段内
  综合多条 Claim 并优先使用语料中的示例与数据；不使用 Markdown 表格；语言跟随 objective。

## 5. 冻结预算（durable 单 Agent）

- `provider_call_limit` 8 → **13**：查询规划 1 + 3 查询 × (embed+rerank) 6 + draft 1 +
  verify 1 + repair 1 + re-verify 1 + writer 1 + audit 1。
- `retrieval_rounds` 1 → **3**；输出预算 32_000 不变（最坏 18,692）。
- Manager 公式不变（子运行 `max_queries=1` 且无 Writer，最坏 `2 + 6N`）。

## 6. 失败语义

- 查询规划失败/解析失败：**不降级**，回退为单查询（仅 objective），记 warning 进 manifest
  （检索是免费前置，放弃多查询不影响交付质量底线）。
- Writer/审计失败：沿用 W1 降级规则不变。
- background 解析违规视为 Writer 失败 → 降级（背景内容不允许带着错误结构进入渲染）。

## 7. 验收

- 单元：planner 解析、background 解析与渲染（○ 标记、独立章节、无引用号）、
  background 违规降级、审计不含 background 文本。
- 端到端：多查询合并证据（两查询去重合并进 Evidence 池）、cited lane C1–C4 不回归、
  Manager `max_queries=1` 调用序列不回归、预算上限 13。
- fixture：`writer_stage_fixtures.json` 全部样本补 `background` 键，新增
  `background_invalid` 样本；新增 planner 规划样本。
