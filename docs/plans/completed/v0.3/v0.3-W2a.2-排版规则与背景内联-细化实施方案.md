# Conflux-Weave v0.3 W2a.2 排版规则与背景内联（A+B 切片）细化实施方案

差距评审结论：排版四项（零加粗、正文无列表、段落文字墙、层级扁平）+ 内容四项中可
机器化的部分（摘要形态、对比句式、通识主线隔离、示意示例受限）。本切片一次交付。

## 1. A 级：写作规则（纯 prompt，schema 仍置于 prompt 末尾）

- 回答摘要：`summary.text` 必须是 3–5 条 Markdown 要点行，每行 `- **加粗结论**：一句支撑`；
  要点必须可由所引 Claim 支撑。
- 小节标题按顺序带中文序号（一、二、三…）。
- 每个小节：至少一个 Markdown 列表（枚举要点）、至少一处 `**加粗**` 关键结论、
  至少一处显式跨来源对比（"与 X 相比，Y…"，材料支持时）。
- 段落：一句一个断言、最多 3–5 短句、目标 ≤250 字符；禁止文字墙与 bullet 墙交替。
- C5 提示保留：cited 段落数字逐字复制。

## 2. B 级：背景内联（合同 + 渲染器 + Writer）

- `ReportParagraph` 增加 `unverified: bool = False`。段落两种形态：
  - verified（默认）：必须携带 1–10 个 claim_ids，句尾渲染引用号，受 C5 与审计覆盖；
  - unverified（`claim_ids` 必须为空）：模型知识段落，可出现在任意小节内部，渲染前缀
    `○`，不受 C5、不进审计覆盖集合、不参与 C3 覆盖率。
- 解析器同时接受 `{text, claim_ids}` 与 `{text, claim_ids, unverified}` 两种键形
  （降低 schema 违规率；`unverified` 缺省 false）。`unverified=true` 但携带 claim_ids
  → 拒绝。
- 背景层允许**示意性通用示例**（JSON 片段、流程演示），须清晰标注为示意、不得含具体
  统计数字；C5 仍只约束 cited 层。
- 结构化 Artifact schema 升级 `…report-document.v4`（段落增加 unverified 字段）；
  报告 Markdown schema 仍为 v2。
- 审计输入展平时跳过 unverified 段落（与尾部 background 同等待遇：标注即边界）。

## 3. 预算

采样实测追加减：Claim 预算扩到 10 后 **Verifier** 也出现 invalid schema / unknown
Claim ID（与 Writer 同因：输出变长导致 schema 服从率下降），且 Verifier 原无重试通道，
异常在付费意图后抛出会触发"结果未知"保护。已加与 Writer 同构的**单次 schema 修复重试**
（附合法 Claim ID 清单），验证器输出上限 1800 → 4096（消除截断型 JSON 损坏）。

冻结预算：`provider_call_limit` 15 → **18**（含 verify/draft 两级修复重试余量）；
`input_tokens` 320k、`output_tokens` 32k → **48k**（最坏 35.5k）；检索轮 3。
Manager 公式不变。

## 4. 验收

- 单元：两种段落键形解析、unverified 违规拒绝（携带 claim_ids）、渲染 ○ 前缀且无
  引用号、审计展平跳过 unverified、C5 跳过 unverified、C3 不受影响。
- 端到端：inline unverified 段落的 v2 报告 + manifest 不回归。
- 人工样例：三题以 `max_subquestions=3` 绕开幂等去重重跑（单 Agent 路径不使用该参数，
  问题文本不变），对比上一轮样例评审排版与主线改善。
