# Conflux-Weave v0.3 W1 研究报告写作阶段（单 Agent Writer + 报告 v2 合同）细化实施方案

## 1. 阶段定位

W1 在已验证的研究链路（retrieve → draft claims → verify → deliver）之后新增一个
**写作/合成阶段（Writer）**，把通过 Verifier 的原子 Claim 组织成用户可读的研究报告，
并在发布前做独立的 faithfulness 审计。失败一律降级回 v1 原子 Claim 报告，不直接发布
未通过校验的叙述文本。

本阶段只覆盖 `VerifiedResearchWorkflow`（单 Agent 路径）。Manager 跨子问题综合
（W2）在本合同稳定后另行实施；本阶段 Manager 子运行显式禁用 Writer。

## 2. 冻结的 Writer 输入/输出 Schema

### 2.1 Writer 输入（user_prompt，JSON）

```json
{
  "objective": "研究问题",
  "claims": [{"claim_id": "claim-0001", "text": "已验证声明"}],
  "evidence": [{"evidence_id": "evidence-0001", "quote": "证据原文"}],
  "citations": [{"display_index": 1, "claim_id": "claim-0001", "evidence_id": "evidence-0001"}]
}
```

只包含被 Verifier 接受的 Claim、其闭包 Evidence 与 Citation。不提供模型自由发挥的
语料来源。

### 2.2 Writer 输出（冻结 JSON Schema）

```json
{
  "summary": {"text": "执行摘要（直接回答）", "claim_ids": ["claim-0001"]},
  "sections": [
    {"heading": "小节标题", "paragraphs": [{"text": "段落", "claim_ids": ["claim-0001", "claim-0002"]}]}
  ],
  "open_questions": ["开放问题（允许：问题是疑问，不是事实断言）"]
}
```

硬约束（解析器 fail-closed）：

- 根键恰好为 `summary`、`sections`、`open_questions`；
- `summary` 与每个段落 `text` 非空，`claim_ids` 非空、无重复、全部属于已接受 Claim 集合；
- `sections` 为 1–8 个，每节 1–8 段，每段引用 1–6 个 Claim；
- `open_questions` 为字符串列表（可为空）。

Writer 的产物以结构化 Artifact 存证（`conflux-weave.research-report-document.v2`），
Markdown 由确定性代码渲染；模型不直接输出 Markdown。

### 2.3 独立审计（faithfulness）输入/输出

审计是一次独立的 Provider 调用，输入为 objective + claims + evidence + citations +
展平后的全部段落（`section_index`/`paragraph_index`/`text`/`claim_ids`），输出：

```json
{"audits": [{"section_index": 0, "paragraph_index": 0, "verdict": "supported|unsupported", "rationale": "…"}]}
```

必须恰好覆盖每个段落一次（summary 记为 section 0 的段落 0）。任一 `unsupported`
即 Writer 失败。

## 3. 冻结的预算

| 调用 | max_output_tokens | temperature | enable_thinking | producer_step_id |
| --- | --- | --- | --- | --- |
| Writer | 4096（适配器上限） | 0.2 | False | `s1-research-write` |
| 审计 | 2000 | 0.0 | False | `s1-research-write-audit` |

- `durable_research.py` 单 Agent 冻结预算 `provider_call_limit` 由 6 调整为 8：
  最坏路径为 embedding + rerank + draft + verify + repair + re-verify + writer + audit。
  输出预算 32000 不变（最坏 4×1800 + 4096 + 2000 = 13296）。
- Manager 公式 `2 + 6 × max_subquestions` 不变（子运行禁用 Writer 后实际最多
  `2 + 4 × max_subquestions`）。
- thinking 保持关闭，保证成本可冻结；放开属于后续调参，不属于本阶段。

## 4. 段落级引用闭合标准（冻结）

- C1：每个 `claim_ids` 非空且 ⊆ 已接受 Claim 集合（段落不得悬空引用）。
- C2：单个段落内 `claim_ids` 无重复。
- C3：全部段落（含 summary）引用的 Claim 并集必须覆盖已接受 Claim 集合：
  - 未覆盖数 ≤ 一半：确定性代码自动追加「补充发现」小节（每条未引用 Claim 一个段落，
    文本即 Claim 原文），并记录 warning；
  - 未覆盖数 > 一半：视为 Writer 失败，降级。
- C4：独立审计覆盖每个段落且全部 `supported`。

`require_closed_citations`（Claim/Evidence/Citation 闭包）语义不变，继续先行执行。

## 5. 失败降级规则（冻结）

以下任一失败 → 降级为 v1 原子 Claim 报告（`render_evidence_report`），
交付 disposition 不变，追加 limitation「报告写作未通过校验，已降级为证据清单视图」，
manifest 记录 `writer_status="degraded"` 与 `writer_degrade_reason`：

1. Writer Provider 调用异常（传输/超时等）；
2. 输出不是合法 JSON 或违反 2.2 任一硬约束（含 C1、C2、C3b）；
3. 审计调用异常、审计覆盖不完整或存在 `unsupported` 段落（C4）。

NO_ANSWER 路径不调用 Writer。降级路径不发布任何叙述文本，v2 结构化 Artifact
也不落盘（避免把未通过校验的文本留存为交付物；Provider 请求/响应 Artifact 仍由
适配器照常存证供审计）。

## 6. 合同新增（兼容式）

- `evidence/contracts.py` 新增 `ReportParagraph`（text, claim_ids）、
  `ReportSection`（heading, paragraphs）、`ReportDocument`
  （objective, summary, sections, open_questions, unreferenced_claim_ids, warnings）。
  `Claim/Evidence/Citation` 语义不变。
- `evidence/validation.py` 新增 `require_closed_report_document(document, claims)`
  （实现 C1/C2 与结构校验）与 `unreferenced_claim_ids(document, claims)`。
- `evidence/delivery.py` 新增 `render_report_document(...)`：确定性渲染 v2 Markdown，
  版本 `conflux-weave.verified-research-report.v2`；v1 渲染器原样保留作为降级路径。
- `report_writer.py`（包根新模块）：Writer/审计编排、解析、降级判定，返回
  `WriterOutcome(document, status, reason, warnings, artifact_refs)`，自身不抛出
  业务异常（内部捕获后转为降级）。

### v2 报告版式（确定性渲染）

`# 研究问题` → 图例（沿用 v1）→ `## 回答摘要` → 各小节（段末追加内联引用
`[n][m]`，n 为 Citation.display_index）→ `## 开放问题`（可选）→ `## 限制` →
`## 来源`（人类可读：display_index、可信度标记、snapshot、locator）→
`### 审计附录（Evidence 汇总）`（v1 机器格式整体后置，供程序审计）。

## 7. 验收 fixture 与测试

`tests/fixtures/writer_stage_fixtures.json` 冻结：canonical Writer 输出、canonical
审计输出、unsupported 审计、未知 Claim 引用、空 claim_ids、非法根键、部分覆盖
七类样本。测试：

- 单元：解析器 fail-closed、闭合校验、未引用检测、v2 渲染器（含内联引用与审计附录）。
- 端到端（`test_research_agents.py`）：happy path v2 报告 + manifest 字段；
  四类失败各自降级；NO_ANSWER 不触发 Writer；Manager 子运行不触发 Writer。
- 存量测试影响：单 Agent happy path 的 SequenceTransport 追加 writer+audit 两个
  payload；Manager 测试不变；`test_durable_research.py` 使用假 executor，不受影响。

## 8. 不做的事

- 不改 Manager 综合逻辑（W2）；不改检索参数与 claim 抽取上限；
- 不改前端（v2 报告仍为 text/markdown，现有 renderAnswer 直接可用；
  摘要折叠、内联引用样式属于 W3）；
- 不把 disposition 改为 partial：disposition 表达研究覆盖度，写作失败只影响
  呈现层，以 limitation + manifest 字段如实记录。
