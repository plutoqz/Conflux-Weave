> 文档状态：`Proposed`

>
> 实施基线：`codex/v0.3-s0-harness@8ea4254`

## 1. 目标与边界

S1 交付第一条真实论文研究闭环：

```text
自然语言论文需求
-> 本地论文库 + 新论文获取
-> 解析、版本化与结构化 Chunk
-> BM25 + Dense Hybrid
-> qwen3-rerank 重排
-> ResearchAgent 研究
-> Verifier 核验 Claim / Evidence / Citation
-> Markdown 深度研究结果
-> Workbench 查看、追问与重新运行
```

S1 的“完整 RAG”指上述从来源到引用交付的完整数据链，不表示支持所有文档格式、
GraphRAG、长期 Memory、通用项目问答或无限自主研究。

### 本阶段必须完成

- 使用现有本地论文库，不以合成语料代替真实 PDF。
- 补充 Agent Harness、Skill、Context Engineering、工具使用、多 Agent 协调和 Agent
  评估方向的新论文及综述。
- 引入可替换的 Embedding 和 Reranker Port，并记录实际调用、成本、延迟和失败。
- 实现 BM25、Dense、Hybrid、Rerank 的可复核结果和版本化索引。
- 将 S0 fixture 替换为真实 ResearchAgent 纵向路径，同时保留 fixture 与旧论文路径。
- 对检索效果、引用质量和 Agent 执行过程建立与产品链路绑定的评估。

### 本阶段不做

- DOCX/HTML 的完整文档笔记和局部修订；进入 P2。
- 项目 RAG、Git 分析和 CodingAgent；进入 P3。
- 长期个人 Memory、统一对话入口、MCP/Skill 对外开放；按 P4/P5 推进。
- GraphRAG、分布式队列和独立评测平台。
- 图片/表格/公式的完整多模态解析；S1 只保留未来多模态所需的页面与 Artifact lineage。

## 2. 已确认输入与事实

### 2.1 本地语料

用户提供的路径写作：

```text
F:\vscode\AcademyHunter\academy\_hunter\papers
```

当前机器上的实际路径为：

```text
F:\vscode\AcademyHunter\academy_hunter\papers
```

2026-08-26 只读盘点结果：

- 179 个 PDF；
- 总大小约 0.605 GiB；
- AcademyHunter SQLite 中有 284 条论文元数据、278 条分析记录；
- 其中 `llm_agent` 方向 136 条；
- 数据库元数据可辅助匹配标题和 arXiv ID，但不能替代 PDF 内容、SourceSnapshot 或
  Conflux-Weave 自己的解析证据。

原目录只读。S1 不移动、改名或删除 AcademyHunter 文件，也不写回其 SQLite/Chroma。
导入时按文件内容哈希去重，将原文、解析结果和索引版本登记到 Conflux-Weave 的
Artifact/SourceSnapshot 体系。

### 2.2 模型配置

三个模型共享 qwen3.7flash 当前使用的 Base URL 和 API Key：

| 角色 | 模型 | 用途 |
|---|---|---|
| Chat / Research / Manager / Verifier | 当前 qwen3.7flash 配置 | 规划、研究、核验和修订 |
| Embedding | `text-embedding-v4` | Query 与 Chunk 向量 |
| Reranker | `qwen3-rerank` | Hybrid 候选重排 |

现有 `ProviderConfig` 只有单一 Chat 模型。S1 增加共享凭据、分角色模型 ID 和独立
Adapter；旧的 `CONFLUX_WEAVE_PROVIDER_MODEL` 继续作为 Chat 模型兼容配置。
Embedding 与 Rerank 的 endpoint、请求字段、响应字段、维度、最大批量和 usage
必须通过真实 Provider preflight 固定，不能仅根据模型名猜测。API Key 不进入日志、
SQLite、Artifact 或前端。

## 3. 目标架构

### 3.1 数据平面

```text
CorpusSource
-> SourceSnapshot
-> DocumentVersion
-> StructuredChunk
-> BM25 Index + Dense Index
-> RetrievalRun
-> RerankResult
-> EvidenceRef
-> Claim / ClaimAssessment / Citation
-> Markdown ResearchReport
```

关键规则：

- PDF 原文、解析文本、Chunk、Embedding 批次、索引和模型原始响应均是版本化 Artifact。
- `IndexManifest` 绑定语料清单哈希、parser/chunker 版本、Embedding 模型、维度和参数。
- 索引可删除后重建，不成为 Evidence 权威来源。
- Evidence 必须定位到 SourceSnapshot、PDF 页码和 Chunk ID。
- AcademyHunter 的旧分析内容只作为可选输入；未经重新核验不能直接成为 Claim 证据。

### 3.2 检索管线

```text
query understanding
-> lexical query + semantic query
-> BM25 top 50 + Dense top 50
-> RRF fusion top 30
-> deduplicate by document/version/chunk
-> qwen3-rerank top 12
-> context assembly top 8
```

以上数字是 S1 默认预算配置，不进入核心合同，可根据真实 token、延迟和评估结果调整。
Reranker 不可用时降级为 Hybrid 结果并显式标注，不能退化为无证据生成。

Dense 使用 LanceDB 作为正式向量数据库，采用本地持久化表和精确/近似向量检索能力。
LanceDB 只负责向量、Chunk ID、SourceSnapshot、文档版本和检索所需的过滤字段；原始
PDF、解析文本、Embedding 批次和模型响应仍由 Artifact Store 保存。SQLite 只追加
IndexManifest、LanceDB 表版本、配置哈希和发布状态，不写入向量或大文本。LanceDB
通过 DenseIndexPort 接入，禁止让 Evidence 直接依赖 LanceDB 行号；每个命中必须回写
稳定的 Chunk ID 和 SourceSnapshot/页码定位。原有本地 JSON Dense 矩阵保留为迁移与
离线回放格式，完成校验后才切换默认读取路径。

多模态 RAG 不在 S1 作为完成条件。S1 的 Chunk/SourceSnapshot 需要保留 page、asset
和 parent-child lineage 字段，使 P2 能在不改变 Evidence 语义的前提下增加图片
Artifact、图像 embedding 和跨模态检索。

### 3.3 Agent 协作

| 角色 | 输入 | 产出 | 不负责 |
|---|---|---|---|
| Manager | 用户目标、预算、语料范围 | 子问题 DAG、停止条件、任务分派 | 直接生成最终事实 |
| ResearchAgent | 子问题、检索工具、Context Bundle | Evidence 集合、候选 Claim、草稿 | 绕过检索和引用检查 |
| Verifier | Claim、Evidence、Citation、原文定位 | ClaimAssessment、冲突和缺口 | 改写证据或静默删除失败 |
| Orchestrator | 计划、消息、状态、预算 | 调度、恢复、交付提交 | 代替模型研究判断 |

简单论文获取不启动模型 Manager，由确定性 Router 直接交给 ResearchAgent。深度研究才
启用 Manager；Verifier 对所有深度研究交付执行核验。默认最多 4 个子问题、3 轮检索、
1 轮补证/修订，这些是可配置预算而不是功能准入规则。

## 4. 需要新增或扩展的合同

只增加 S1 有实际消费者的合同：

- `CorpusManifest`：语料 ID、来源、文件哈希、导入状态和失败原因。
- `DocumentVersion` / `StructuredChunk`：文档版本、页码/章节、文本哈希和父子关系。
- `EmbeddingSpec` / `EmbeddingBatchResult`：模型、维度、批次、usage 和 Artifact 引用。
- `IndexManifest`：语料版本、sparse/dense 索引版本、LanceDB 数据库/表版本、距离度量和
  发布状态。
- `DenseIndexPort`：向量写入、批量 upsert、相似度检索、过滤、删除/重建和健康检查；
  第一版实现为 LanceDB，保留离线 JSON 回放 Adapter。
- `RetrievalRequest` / `RetrievalResult`：各路命中、融合排名、过滤和耗时。
- `RerankResult`：输入候选、分数、模型和降级状态。
- `ResearchPlan` / `CoverageReport`：子问题、证据覆盖、缺口和停止原因。
- 复用现有 `ClaimAssessment`、`EvidenceRef`、`Citation` 与
  `require_closed_citations`，不复制 Evidence 语义。

SQLite migration 只追加语料、文档版本、Chunk 元数据和索引清单；大文本和向量保存在
Artifact/文件系统，不写入消息正文或 SQLite JSON 大字段。

## 5. 分阶段实施

### S1.0 事实基线、Provider 与评估合同

实施：

- 形成 179 篇 PDF 的只读 manifest，核对文件哈希与 AcademyHunter 元数据匹配率。
- 对 Chat、Embedding、Reranker 分别执行一次最小 Provider preflight。
- 冻结 parser/chunker/index 模型配置和 Artifact schema version。
- 建立第一版评估集：检索案例、无答案案例和 Agent 任务案例。
- 记录现有 BM25、旧论文 Runtime 和 S0 Harness 的可复用/替换边界。

验收：

- 179 个文件全部有 `importable/duplicate/parse_failed/metadata_missing` 等明确状态。
- 三类 Provider 的 endpoint 与响应合同有原始 Artifact；未成功的能力标记
  `live_blocked`，不得由 fixture 冒充。
- 评估集具有来源、标注依据、版本和 held-out 划分，但不阻塞后续功能编码。

### S1.1 语料补充、导入与解析

实施：

- 从 arXiv、Crossref 和可合法下载的作者/会议页面补充论文。
- 主题覆盖 Harness/Runtime、Context Engineering、Tool/Skill、Multi-Agent、Agent
  Evaluation；优先 2025-2026，兼顾关键早期工作和综述。
- 至少覆盖 3 篇综述，以及每个主题至少 2 篇代表性研究；下载前按 arXiv ID、DOI 和
  内容哈希与本地 179 篇去重。
- 下载写入 Conflux-Weave 管理的语料目录，不写入 AcademyHunter。
- 解析 PDF，生成页码/章节可定位的 StructuredChunk 和失败报告。

验收：

- acquisition manifest 记录检索式、来源 URL、许可/可访问状态、时间和内容哈希。
- 每个成功 Chunk 可回溯到 PDF 页码与 SourceSnapshot；所有失败均保留。
- 重复导入不重复下载、解析或生成 Embedding。

### S1.2 Sparse/Dense 索引

实施：

- 将现有 BM25 扩展到版本化 Chunk corpus。
- 实现 `text-embedding-v4` Adapter、批处理、缓存、限流和维度校验。
- 创建可重建 Dense Index 和 IndexManifest；以 LanceDB 表作为默认 Dense 后端，保留
  当前 JSON 矩阵作为迁移输入和故障回放。
- 实现 Chunk ID -> LanceDB row -> SourceSnapshot/page 的稳定 lineage 和过滤字段。
- 支持按语料、时间、论文、章节和来源过滤。

验收：

- 相同 manifest 与配置重复构建得到同一逻辑索引版本。
- 新增/变更论文只重算受影响 Chunk。
- Embedding 部分失败不会发布半成品索引；可从已完成批次恢复。
- LanceDB 表发布采用临时表/版本化表名，完整校验后原子更新 IndexManifest；失败批次
  不得进入默认检索表。
- JSON 矩阵与 LanceDB 检索结果在冻结案例上完成一致性对比后，才宣布 LanceDB 为
  默认 Dense 路径。

### S1.3 Hybrid、Rerank 与 RAG 评估

实施：

- 形成 BM25、Dense、RRF Hybrid 和 `qwen3-rerank` 四段结果。
- 保留每段排名，避免只保存最终 top-k 而无法诊断召回问题。
- 实现 context assembly、去重、证据预算和无答案判断。
- 运行检索消融和 RAG 评估，形成案例级失败清单。

验收：

- 报告 Recall@k、MRR、nDCG@k、无答案准确性、Evidence coverage、延迟和调用成本。
- Hybrid/Rerank 即使未优于单路结果也保留为可配置能力；评估用于调参和默认策略，
  不把已明确需要的功能重新变成准入实验。
- Reranker 失败可降级，且结果明确说明未重排。

### S1.4 多智能体研究与 Agent 评估

实施：

- 将 Manager、ResearchAgent、Verifier 作为真实 Agent Profile 接入 S0 Harness。
- 持久化 ResearchPlan、Context Bundle、ToolResult、MessageEnvelope、CoverageReport 和
  ClaimAssessment。
- 实现 `plan -> research -> verify -> one repair -> deliver`。
- 加入取消、token/时间预算、工具失败、Context 截断和进程重启回放。
- 运行 Agent 任务与轨迹评估。

验收：

- 未授权 Tool 调用为 0，重复副作用为 0，消息和 Artifact 可重放。
- 所有最终 Claim 要么有 Citation 和 Assessment，要么明确标记为不确定/模型知识并
  从证据性结论中移除。
- 任务完成、计划有效性、工具成功率、证据覆盖、修订收益、token、延迟和恢复结果可查。

### S1.5 Workbench 与真实交付

实施：

- 新 Research 页面展示语料范围、论文、检索轮次、引用、可信度、限制和成本。
- 支持论文获取与深度研究两种任务；支持刷新、取消、追问和基于原 Run 重新研究。
- 对本地语料、新下载语料和混合语料执行真实 qwen3.7flash 任务。

验收：

- 至少完成 8 个真实任务，其中包含本地库、新论文、跨论文综合和无答案场景。
- Citation closure 为 1.0；人工复核的关键 Claim 不允许存在无证据支持项。
- 所有任务保存模型、Prompt、索引、语料、原始响应、token、耗时和失败记录。
- Workbench 在桌面与移动端均可完成任务并在重启后恢复结果。

### S1.6 优化与阶段收口

- 根据 S1.3-S1.5 的失败类型优化 retrieval、chunk、rerank、Context 或 Agent 调度。
- 保留 BM25-only、Dense-only、Hybrid、Hybrid+Rerank 和单/多 Agent 对比。
- 同步项目状态，明确哪些结果是 offline、replay 或 validated_live。
- 形成 P2 文档分析与可持续笔记的输入合同，包含图片 Artifact、页面 asset lineage
  和跨模态检索 Port，但不在 S1 内实现图像模型调用。

### 后置安排：P2 多模态 RAG（图片优先）

- P2.0：PDF 页面资产抽取、图片哈希、页码/区域坐标、父 Chunk 关系和失败报告；原图
  与缩略图进入 Artifact Store，OCR 仍是可选能力。
- P2.1：增加可替换 `ImageEmbeddingPort` 与图文联合 `MultimodalRetrievalResult`，
  以 LanceDB 存储 image/text 向量和 modality/filter 字段；不得复制 Evidence 语义。
- P2.2：实现文本->图片、图片->文本和图文混合召回，接入 rerank/context assembly，
  保留 modality、页码、区域和 Artifact 引用。
- P2.3：用真实论文图表案例评估 image Recall@k、跨模态 Evidence coverage、引用定位
  正确性、延迟、成本和无答案准确性；扫描 PDF、复杂公式和表格失败必须单独统计。
- P2 完成条件：文本 RAG 回归不退化，图片证据可定位、可复核，模型和索引版本可重建；
  未达到条件时保持文本-only 默认路径。

## 6. RAG 与 Agent 评估引入时间

评估从 S1 开始即存在，但分层进入，不形成独立产品线：

| 阶段 | RAG 评估 | Agent 评估 |
|---|---|---|
| S1.0 | 建立真实案例、标注和现有 BM25 基线 | 建立任务/轨迹 schema 和成本基线，不评价尚未实现的多 Agent |
| S1.1-S1.2 | 解析覆盖、Chunk lineage、索引完整性、Embedding 缓存/失败 | 仅验证 Tool、Context、消息合同 |
| S1.3 | 正式引入 Retrieval/RAG 评估与四段消融 | 检查 Research Tool 调用结果，不作完整协作结论 |
| S1.4 | 评价 Agentic RAG 的缺口查询与补证收益 | 正式引入 Manager/Research/Verifier 任务与轨迹评估 |
| S1.5 | 真实端到端 faithfulness、Claim support、Citation 和无答案评估 | 真实任务成功率、协作收益、恢复、token 与延迟评估 |
| S1.6 | 用失败样本驱动检索和 Context 优化 | 用失败轨迹驱动调度、角色和预算优化 |

默认先使用确定性指标、案例级对比和人工复核。Ragas 可在 S1.5 作为
faithfulness/context relevance 的辅助 Adapter；DeepEval 或 LLM-as-a-Judge 可在 S1.4
之后辅助评估 Agent 结果与轨迹。它们均不拥有 Run 状态，不是生产依赖，且不能替代
Citation closure、原始 Evidence 或人工关键 Claim 复核。

## 7. 测试与证据

- 单元：URI/manifest、parser/chunker、Embedding/Reranker 响应、fusion、Citation。
- 合同：Provider、Tool、Context、Message、IndexManifest、恢复与幂等。
- 集成：PDF -> index -> retrieval -> Evidence -> Markdown。
- 回放：Provider 超时、部分 embedding、rerank 失败、进程重启、缓存命中和无答案。
- Live：真实 PDF、真实下载源、真实三个模型和 Workbench 全链路。

证据写入忽略目录 `var/acceptance/v0.3-s1/`；冻结的小型案例合同可进入
`datasets/regression/`。任何正式结果记录源码 revision、语料 manifest hash、模型、
Prompt、参数、预算、Run ID、Artifact hash 和失败案例。

## 8. 风险、停止条件与回滚

| 风险/条件 | 处理 |
|---|---|
| GitHub/论文源网络不可用 | 继续本地 179 篇的 ingest/RAG；新论文下载标记 external_blocked |
| Embedding/Reranker endpoint 不兼容 | 停止 live 声明，保留 Adapter fixture 与原始响应，不伪造成功 |
| LanceDB 表损坏、版本不兼容或迁移失败 | 保留旧 JSON/旧表版本，IndexManifest 不切换默认版本，进入离线回放或人工恢复 |
| PDF 无文本、加密或损坏 | 标记 parse_failed；S1 不临时引入 OCR 掩盖问题 |
| 本地库元数据与 PDF 不一致 | PDF hash/SourceSnapshot 为权威，AcademyHunter 元数据标记冲突 |
| 多 Agent 成本或延迟过高 | 简单任务走单 ResearchAgent；复杂任务才启用 Manager/Verifier |
| Citation 闭合但语义不支持 | Verifier 产生 ClaimAssessment；关键 Claim 人工复核，不以闭合率替代支持度 |
| 计划外修改 S0 核心状态语义 | 暂停并形成 ADR，不在 S1 内隐式建立第二套 Runtime |

回滚策略：

- 新研究路径使用独立 task kind/feature flag，旧 `/api/v1/tasks/research` 保持兼容。
- SQLite 只做追加 migration；LanceDB 表、索引和向量是可重建派生产物，Artifact 保留
  批次和发布证据。
- AcademyHunter 始终只读，新下载语料和 Artifact 使用独立根目录。
- Chat、Embedding、Reranker Adapter 可独立禁用；降级状态进入 Delivery limitations。
- 每个 S1.x 形成可检出的提交和验收点，不删除失败结果或旧索引版本。

## 9. S1 完成定义

S1 仅在以下事实同时成立时标记 `validated_live`：

1. 本地论文和新增论文均以版本化 SourceSnapshot 进入真实数据链。
2. BM25、Dense、Hybrid、Rerank 均真实运行且结果可追溯。
3. ResearchAgent 与 Verifier 完成真实 Claim/Evidence/Citation 交付；复杂任务使用 Manager。
4. RAG 与 Agent 评估已在对应阶段运行并保留原始结果和失败样本。
5. 真实 qwen3.7flash、`text-embedding-v4`、`qwen3-rerank` 的模型、token、延迟和错误可查。
