## 0. 这一份方案回答的核心问题

1. **为什么 Conflux-Weave 既需要 Skill 又需要 MCP，二者的边界是什么？**  
   - **Skill（高阶业务工作流包）**：是面向**领域研究者**的声明式能力封装。它不只是简单的单次 Prompt，而是将特定学术任务的最佳实践（如“文献对比综述”、“代码架构坏味道审计”、“LaTeX 语法与符号一致性校验”）固化为包含系统提示模版、依赖工具链、入参/出参 Schema、自检规则与紧凑预算约束的**版本化能力包**。
   - **MCP（标准化工具与数据接入协议，Model Context Protocol）**：是**协议级的通用互联总线**。它负责打通异构生态的边界。Conflux-Weave 需要同时扮演双重角色：
     - **MCP Client**：动态挂载外部生态（如本地文件系统、Git 仓库服务、学术检索、数据库等标准 MCP Server），安全地将外部工具映射为 Harness `ToolSpec` 供系统内所有 Agent 调用；
     - **MCP Server**：对外暴露 Conflux-Weave 的核心学术资产（LanceDB 论文混合检索、图文证据提取、代码架构拓扑解构、分层记忆），允许 Cursor、Claude Desktop 等外部宿主无缝调用。
2. **为什么多 Agent 协作必须从目前的“同步阻塞瀑布流”进化为“异步事件驱动（Async Event-Driven）”？**  
   在复杂的综合研究场景中，单靠同步循环调用会导致：① 长时间 HTTP 连接脆弱，网络微波动易引发整链崩溃；② 无法发挥多任务并行优势（例如同时研读 5 篇相关论文或同时体检 4 个代码子模块）；③ 用户无法实时感知中间状态与部分交付物。必须依托既有的 SQLite `agent_messages` 信封，升级为非阻塞异步消息队列与并发调度引擎。
3. **如何彻底杜绝外部 MCP 引入的安全逃逸与资费失控？**  
   坚持**沙箱边界与确定性预算控制**：
   - 外部 MCP 工具调用必须经过 `ToolGateway` 鉴权与参数校验，严禁未经沙箱隔离的任意本地 shell 执行；
   - 外部调用明确标注 `ToolSideEffect`（幂等读 / 外部写 / 付费未知），并计入 Run 的硬性预算账本（`BudgetLedger`）；
   - 对具有破坏性的写入动作强制触发人在回路（HITL）确认。
4. **长程并发多 Agent 任务如何实现优雅终止（Graceful Termination）与断点续跑（Resume）？**  
   每个 Agent 在其步进循环（Step Loop）的安全点检查中断信号。收到 `terminate_requested` 时，主动将已生成的中间草稿保存为 Artifact、持久化当前已捕获的证据并释放租约，保证状态零损坏；在发生崩溃重启时，依据消息幂等键和任务依赖图（DAG）仅重放未完成分支，避免重复调用扣费。

## 1. 核心设计原则与安全红线

1. **协议解耦与原生轻量 (Protocol Independence & Zero Bloat)**：
   - MCP 协议层作为独立 Gateway 适配器实现，不侵入核心 Harness 运行时与 SQLite 领域契约；
   - 维持 100% 纯本地离线可用性，内部通信与默认 Skill 不依赖任何外部 CDN 或第三方闭源平台。
2. **双向互联对称性 (Bi-directional MCP Symmetry)**：
   - **入向 (Inbound/Client)**：外部 MCP Server 的 Tools 自动投影为 Harness `ToolSpec`，受 ToolGateway 权限约束；
   - **出向 (Outbound/Server)**：提供标准的 JSON-RPC / SSE 传输端点，使外部 AI 宿主能够将 Conflux-Weave 作为专业学术文献知识库与项目认知服务使用。
3. **确定性拓扑编排与紧凑预算 (Deterministic DAG & Hard Budgeting)**：
   - Manager 编排的任务必须是可解析的有限有向无环图（DAG），严禁产生无限循环递归；
   - 并行 Worker Agent 的总并发数受硬性限额控制（默认最大并发度 ≤ 3），单次 Run 的总耗时与 token 预算严格受 `BudgetLedger` 约束。
4. **人在回路 (HITL) 与写入操作物理核准**：
   - 具有本地写操作、代码补丁应用、外部数据修改的 Skill 或 MCP 工具，必须挂起任务并向用户发送 `needs_input` 确认信封，未经用户物理点击批准严禁自动执行。

### 支柱 1：声明式 Skill 架构与生命周期 (Declarative Skill Architecture)

Skill 是高阶专业能力的封装。支持内置（Built-in）与用户自定义（Custom）加载：

```text
weave://system/skills/<skill_id>/
├── skill.yaml               # 核心清单：元数据、参数契约、依赖工具、预算估算
├── prompt.md                # 角色专业系统提示词与步骤范式
├── rules.json               # 产物自检与验证约束规则
└── examples.json            # 少样本演示（Few-shot Demonstrations）
```

1. **清单文件规范 (`skill.yaml`)**：
   ```yaml
   skill_id: "literature_comparative_survey"
   version: "1.0.0"
   name: "文献对比综述工作流"
   description: "跨多篇学术论文进行核心指标、实验设计与理论局限的结构化横向对比"
   category: "research"
   author: "Conflux-Weave Core"
   input_schema:
     type: "object"
     properties:
       paper_ids:
         type: "array"
         items: { type: "string" }
         description: "待比对的论文 ID 列表 (2-5 篇)"
       focus_dimensions:
         type: "array"
         items: { type: "string" }
         description: "关注的比对维度，如 ['准确率', '训练显存', '收敛轮数']"
     required: ["paper_ids"]
   required_tools:
     - "rag_hybrid_search"
     - "get_paper_evidence"
     - "multimodal_image_retrieval"
   default_budget:
     max_tokens: 8000
     max_steps: 12
     estimated_time_seconds: 60
   ```
2. **首批交付的 3 个内置权威 Skill**：
   - **`literature_comparative_survey`（多篇文献对比综述）**：提取多篇目标论文的核心假设、实验数据与局限，输出高密度的 Markdown 对比矩阵表与结论总结。
   - **`code_architecture_audit`（架构治理与实现体检）**：调用 `ProjectAgent` 与 AST 工具，排查上帝文件、契约悬空接口与隐式环境变量泄漏，输出带严重度分级的体检报告与解耦建议。
   - **`latex_paper_polisher`（LaTeX 论文表达润色与公式校验）**：分析段落逻辑连贯性，核验公式符号定义闭环，生成符合顶级学术会议文风的建议 Patch。

### 支柱 2：MCP Gateway 双向协议网关 (Bi-directional MCP Gateway)

遵循标准 Model Context Protocol 规范，实现 Client 与 Server 双重角色：

```text
                               外部生态 (Cursor / Claude Desktop)
                                                ▲
                                                │ (调用 CW 学术能力)
                                                ▼
                                   ┌─────────────────────────┐
                                   │   CW MCP Server 模式    │
                                   │ • conflux_search_papers │
                                   │ • conflux_get_evidence  │
                                   │ • conflux_project_walk  │
                                   └────────────┬────────────┘
                                                │
                                    Conflux-Weave 运行时内核
                                                │
                                   ┌────────────┴────────────┐
                                   │   CW MCP Client 模式    │
                                   │ • 动态加载外部工具      │
                                   │ • 沙箱鉴权与预算约束    │
                                   │ • 转换为 Harness Tool   │
                                   └────────────┬────────────┘
                                                ▲
                                                │ (接入外部数据与能力)
                                                ▼
                               外部 MCP Server (Filesystem, Git, Fetch, DB)
```

1. **MCP Client（入向集成）**：
   - 支持 `stdio`（子进程标准输入输出）与 `sse`（HTTP Server-Sent Events）两种标准 MCP 传输协议；
   - 自动向外部 Server 发送 `tools/list`，动态捕获工具名称、描述与 JSON Schema；
   - 封装为 Harness 原生 `ToolSpec`，注入至对应 Agent 的 `available_tool_ids` 中；
   - 每次调用由 `ToolGateway` 实施安全隔离与耗时计时。
2. **MCP Server（出向暴露）**：
   - 暴露端点：`/api/v1/mcp/sse` 与 `/api/v1/mcp/messages`；
   - 向外部宿主公开的核心 Tools：
     - `conflux_search_papers(query, top_k)`：执行 BM25 + Dense + RRF 混合检索，返回高置信度学术 Chunk；
     - `conflux_get_paper_evidence(paper_id, section_or_page)`：获取带有来源快照和视觉图像的权威证据；
     - `conflux_project_walkthrough(project_id)`：返回项目的模块依赖拓扑与学术理论映射关系；
     - `conflux_get_user_preferences()`：安全获取用户在设置中心核准的长期偏好约定。

### 支柱 3：多 Agent 异步事件总线与并发调度 (Async Event Bus & DAG Scheduling)

将同步阻塞流水线升级为基于事件驱动的协作框架：

1. **事件驱动通信信封与存储 (SQLite Migration v8)**：
   - 复用既有 `agent_messages` 物理表，扩充事件广播支持；
   - 新增 `agent_events` 表，记录跨 Agent 状态流转轨迹与心跳信号：
     - `event_id`, `run_id`, `agent_id`, `event_type`, `payload_json`, `created_at`。
2. **任务依赖 DAG 并发解析器 (DAG Task Scheduler)**：
   - Manager 生成的分步计划支持声明 `depends_on: ["step-1", "step-2"]`；
   - 调度引擎依据拓扑排序自动识别**就绪队列（Ready Queue）**；
   - 无相互依赖的子任务利用 `asyncio.TaskGroup` 或工作线程池并发启动，最大并发度严格受配置限额控制（默认上限 3）；
   - 子任务通过 `ArtifactRef` 产出引用，后继任务根据引用只读加载所需切片，杜绝全量历史堆叠。
3. **优雅终止（Graceful Termination）与断点续跑（Durable Resume）**：
   - 当用户点击【取消】或触发超时时，向正在执行的 Agent 投递 `terminate_requested` 信号；
   - Agent 在完成当前原子步骤后主动交还控制权，写入 `partial` 交付物并释放锁；
   - 若系统异常中断，重新启动任务时，根据 SQLite 中已成功完结的 Step 记录直接装配上下文，跳过已完成节点，继续调度未完成的 DAG 分支。

## 3. 数据合同与架构落点

### 3.1 核心数据结构

```python
# 1. Skill 规约与定义
@dataclass(frozen=True, slots=True)
class SkillSpec:
    skill_id: str
    version: str
    name: str
    description: str
    category: str              # "research" | "governance" | "writing" | "utility"
    author: str
    input_schema: dict[str, Any]
    required_tools: tuple[str, ...]
    prompt_template: str
    rules: tuple[str, ...]
    default_budget: BudgetLedger
    is_builtin: bool = True
    schema_version: str = "conflux-weave.skill.v1"

# 2. MCP Server 外部连接配置
class MCPTransportType(str, Enum):
    STDIO = "stdio"
    SSE = "sse"

@dataclass(frozen=True, slots=True)
class MCPServerConfig:
    server_id: str
    name: str
    transport_type: MCPTransportType
    command: str | None = None
    args: tuple[str, ...] = ()
    url: str | None = None
    env_vars: dict[str, str] = field(default_factory=dict)
    enabled: bool = True
    timeout_seconds: float = 30.0

# 3. DAG 任务调度节点
@dataclass(frozen=True, slots=True)
class DAGTaskNode:
    node_id: str
    agent_type: str
    objective: str
    depends_on: tuple[str, ...]
    skill_id: str | None
    input_payload: dict[str, Any]
    budget: BudgetLedger
    status: str = "pending"   # pending | running | completed | failed | skipped
```

### 3.2 数据库迁移规约 (SQLite Migration v8)

在 `src/conflux_weave/runtime/sqlite_migrations.py` 中追加 `version=8`：

```sql
-- Migration 8: v03_skills_and_mcp_gateway
CREATE TABLE skills (
    skill_id TEXT PRIMARY KEY,
    version TEXT NOT NULL,
    name TEXT NOT NULL,
    description TEXT NOT NULL,
    category TEXT NOT NULL,
    author TEXT NOT NULL,
    input_schema TEXT NOT NULL,       -- JSON
    required_tools TEXT NOT NULL,     -- JSON Array
    prompt_template TEXT NOT NULL,
    rules TEXT NOT NULL,              -- JSON Array
    is_builtin INTEGER NOT NULL DEFAULT 1,
    status TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active', 'disabled')),
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);

CREATE TABLE mcp_servers (
    server_id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    transport_type TEXT NOT NULL CHECK (transport_type IN ('stdio', 'sse')),
    command TEXT,
    args TEXT,                        -- JSON Array
    url TEXT,
    env_vars TEXT,                    -- JSON (敏感数据脱敏保存)
    enabled INTEGER NOT NULL DEFAULT 1,
    tools_cache TEXT,                 -- JSON Array 缓存探测到的工具
    last_connected_at TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);

CREATE TABLE agent_events (
    event_id TEXT PRIMARY KEY,
    run_id TEXT NOT NULL REFERENCES runs(run_id) ON DELETE CASCADE,
    agent_id TEXT NOT NULL,
    event_type TEXT NOT NULL,
    causation_event_id TEXT,
    payload_json TEXT NOT NULL,
    created_at TEXT NOT NULL
);

CREATE INDEX idx_agent_events_run ON agent_events(run_id, created_at);
```

## 5. 分阶段实施路线图与验收评测矩阵 (P5.0 ~ P5.5)

整个 P5 的交付划分为 6 个严格递进的切片，恪守“先契约单测、后端到端验证、全量回归不降级”的安全原则：

### 阶段 P5.0：细化方案评审与架构契约冻结（本方案）
- **目标**：冻结 Skill 声明格式、MCP 双向协议映射、SQLite Migration v8 与 DAG 调度算法；
- **验收标准**：文档评审通过，合入版本控制受控目录。

### 阶段 P5.1：声明式 Skill 架构与执行引擎落地
- **目标**：
  - 实现 SQLite Migration v8 中 `skills` 相关部分与 `SkillRegistry`；
  - 交付 3 个内置权威学术 Skill（文献对比综述、代码架构审计、LaTeX 论文润色）；
  - 实现 `SkillRunner`，将其无缝转换为标准 Harness 任务。
