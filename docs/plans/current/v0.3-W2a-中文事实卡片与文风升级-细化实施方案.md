# Conflux-Weave v0.3 W2a 中文事实卡片与文风升级（Distill + Writer 输入重构 + C5）细化实施方案

针对单 Agent 报告的翻译腔、排版可读性与内容质量，本阶段落地两位专家意见中可机器化
保证的部分；Polish 按专家二建议门控后置。

## 1. 中文事实卡片（Distill）

验证通过后、写作前新增一次 LLM 调用（`s1-research-distill`，temp 0，4096 tokens）：

- 输入：accepted claims + evidence 原文引文。
- 输出（fail-closed 解析）：
  `{"cards":[{"evidence_id","zh_summary","zh_key_points":[…],"terms":[{"en","zh"}],"scope_limits"}]}`
  每 张卡片必须绑定已知 evidence_id（1–16 张）；zh_summary ≤2000 字符；key_points ≤8×500；
  terms ≤12 对（各 ≤100）；scope_limits ≤500。
- 卡片要求：用自己的话总结、禁止逐句翻译；完整保留原文的限定条件与适用范围；数字与
  标识符逐字保留；不得添加引文之外的事实。
- 产物存证：`conflux-weave.evidence-cards.v1`（含请求/响应 Artifact）。
- **不是新事实权威**（专家二修正#1）：卡片只供 Writer 理解输入；段落审计与 C1–C4 仍以
  原始 Claim/Evidence 原文为基准，卡片译错只会在审计处暴露并整体降级，因此卡片无需
  自建独立校验层。
- 失败语义：任何解析/Provider 失败 → `distill_status="failed"`，Writer 回退到直接读
  英文引文的现状路径，**不阻断交付**（manifest 记录 distill_status 与原因）。

## 2. Writer 输入重构

- 卡片可用时：Writer 用户消息包含中文卡片 + Claim 原文，**不再注入英文引文原文**；
  审计消息保持原始 Claim/Evidence 原文不变（回溯能力不丢）。
- 卡片不可用时：维持 W1.5 行为（引文直读）。
- 术语表：来自卡片 `terms`，正文首次出现用"中文名（English）"格式。
- `writer_prompt_version = "writer-zh-cards-v1"` 记入 document artifact 与 manifest，
  冻结以版本号管理；未通过人工样例评审前不得上调冻结版本。

## 3. 文风与排版硬规则（写入 Writer system prompt，正向+反向）

正向：先给判断再给支撑；明确中文主语；段落 3–5 句；叙述与短列表混排，禁止文字墙与
bullet 墙交替；归因具体到所引 Claim 的方法/论文，禁止"研究表明"式模糊归因；完整保留
限定与不确定性；末节必须收束结论。

反向（翻译腔特征清单）：逐句对应原文语序；"本文提出了一种…用于解决…"摘要腔；
"基于…的…的…"多重"的"堆叠；连续三句以上被动句。

格式：允许代码围栏（前端已支持）；Markdown 表格仍禁止（前端不支持，W4 解禁）；
引用号由渲染器统一追加句尾。

## 4. C5 数字漂移校验（确定性，回应"数字漂移"验收项）

cited 段落（summary + sections）文本中的每个数字串（`\d+(?:\.\d+)?`）必须能在该段
所引 Claim 原文与其对应 Evidence 引文中逐字找到；行首列表标记与 `[n]` 引用号在检查前
剥离。违规 → Writer 失败 → 降级。background 层不检查（其定位是未核验补充，由 prompt
禁止具体统计数字 + 显式标注约束）。范围之外已知残留风险：千分位、百分数改写——prompt
要求逐字复制数字，残余场景宁可降级不可放行。

## 5. 冻结预算（durable 单 Agent）

`provider_call_limit` 13 → **15**（+1 Distill +1 Writer schema 修复重试：实测 10 Claim
长输入下模型 JSON schema 服从率下降，三次首跑全部 schema 违规；修复重试只规范化格式，
C1–C5 与审计门照旧把关，且 schema 指令移至 prompt 末尾）；`input_tokens` 160_000 → **320_000**
（实测 W2a 全链路输入 162k–182k：rerank 请求计入全部候选 chunk 文本，多次调用携带引文，
首版估算过紧，两次真实 Run 因此 budget overage 失败）；检索轮次 3、输出预算 32_000 不变
（最坏 22,788）。每段 Claim 引用上限 6 → **10**（Claim 预算扩到 10 后，摘要综合多处
来源是正常形态，首跑实测 10 Claim 全过但摘要引用超 6 被误降级）。Manager 不受影响。

## 6. 验收

- 单元：卡片解析 fail-closed（未知 evidence_id/缺字段/超限）、C5 命中与列表标记豁免、
  Writer 输入含卡片且不含英文引文、审计输入仍含英文引文、distill 失败回退不阻断。
- 端到端：distill 成功/失败两路径 manifest 字段正确、预算内调用计数正确。
- **人工样例评审（prompt 冻结前置条件）**：3 个固定测试问题
  （①智能体的skill是怎么发挥作用的？②智能体的harness设计应该包括哪些方面的内容？
  ③当前一个智能体的记忆架构应该怎么设计）在重启后的服务上跑真实 Run，产出 before/after
  样例交用户评审；评审通过后 `writer_prompt_version` 冻结为正式版本。
