# Conflux-Weave v0.3 P2.0 图片资产与多模态 RAG 范围冻结

## 1. 当前基线

- S1 研究、证据链和 Workbench 已通过当前有界验收。
- PDF 当前只生成页级文本 `DocumentSegment`，Markdown 当前按标题生成文本段。
- `SourceSnapshot`、`ArtifactRef`、`EvidenceRef` 和 `RetrievalDocument` 已提供文本 lineage 基础。
- P2.0 不修改既有文本-only 检索默认路径；多模态能力未通过回归前，文本路径继续作为稳定入口。

## 2. 目标

P2.0 只建立一条可审计的图片资产链路：

```text
PDF -> 页面/图片 Artifact -> 图片资产元数据 -> 父 Chunk lineage
    -> 可选图像向量 -> modality/filter 检索 -> Evidence/报告引用
```

首个版本必须能够回答：图片来自哪个文档、哪一页、哪个区域、哪个父文本段，
以及图片 Artifact 是否能被原样取回。图像 embedding 和跨模态检索建立在这条链路之上，
不能绕过它。

## 3. 冻结的数据契约

### 3.1 `DocumentAsset`

最小字段：

- `asset_id`：内容寻址或稳定派生 ID；
- `document_id`、`source_snapshot_id`；
- `artifact_ref`、`media_type`、`content_hash`；
- `page`；
- `bbox`：页面坐标系中的 `x/y/width/height`，未能提取时为 `null`；
- `caption`：原始图注文本，可为空；
- `parent_segment_ids`：与文本段的显式 lineage；
- `extraction_method`、`extraction_status`、`warnings`。

### 3.2 索引记录

在现有 LanceDB 文本记录基础上增加：

- `modality`: `text | image`；
- `asset_id`；
- `parent_chunk_ids`；
- `source_snapshot_id`；
- `locator_json`；
- 图像向量及 `embedding_model`、`dimensions`；
- 可复现的 Index Manifest 和 corpus hash。

文本记录字段语义保持不变，旧索引可以继续读取。

## 4. 实施阶段

### P2.0-A：图片抽取与 lineage

- 从真实 PDF 抽取嵌入图片和页面区域；
- 图片原始字节写入 Artifact Store；
- 生成 `DocumentAsset` 清单及父文本段关联；
- 记录无法抽取、无 bbox、重复图片、扫描页等状态；
- 不做 OCR，不调用模型。

验收：真实 PDF 的图片数量、页码、哈希、Artifact 可回读，且每个资产的来源链路可追溯。

### P2.0-B：图片查看与 Evidence 展示

- Workbench Evidence Inspector 支持图片 Artifact 预览；
- 展示页码、区域、图注、父 Chunk 和 SourceSnapshot；
- 图片无法显示时保留元数据和可行动错误，不丢 Evidence。

验收：桌面、移动端和打印模式不破坏现有文本报告；图片证据可从引用定位到原始 Artifact。

### P2.0-C：可替换图像 embedding

- 新增 `ImageEmbeddingPort`，Provider 作为可替换实现；
- 记录模型、维度、批次响应 Artifact、版本和失败原因；
- LanceDB 使用 `modality` 和来源字段过滤；
- 先做 image-only / text-to-image 小型评估，不改变默认文本检索。

验收：向量与资产一一对应，重建结果可校验，失败批次不发布为完整索引。

### P2.0-D：有限跨模态检索

- 支持文本查询找图片、图片查询找文本的最小路径；
- 结果必须回到现有 Evidence/Citation 合同；
- 保留 text-only baseline、输入、预算、模型和原始响应。

验收：固定评估集上比较 text-only 与跨模态结果；不以图片数量或生成描述数量作为质量指标。

## 5. 失败边界与非目标

- OCR、扫描 PDF、复杂公式/表格作为独立失败类别记录，不用模型描述替代原图。
- 不在 P2.0 引入通用图表、KPI 自动抽取、Mermaid、Memory、Skill/MCP 或前端框架迁移。
- 不删除或覆盖历史 Artifact、文本索引和既有验收结果。
- 不把图片 embedding 或跨模态检索的离线结果表述为真实能力，除非完成对应 live 验收。

## 6. 第一个验收点

P2.0-A 的实现前置是冻结一份真实 PDF fixture 清单，至少覆盖：

1. 含嵌入图片和图注的正常 PDF；
2. 含重复图片或无法关联父段的 PDF；
3. 扫描页或无可提取文本的 PDF。

每份 fixture 记录文件哈希、页数、预期图片资产、允许失败类别和输出目录。
在该清单与 `DocumentAsset` schema 通过后，才开始写抽取器和 Artifact lineage 实现。
