# Conflux-Weave v0.3 P2 图片资产与多模态 RAG 细化实施方案

- 文档状态：`in_progress`
- 编制日期：2026-09-08
- 执行状态：`p2.0_0_and_p2.0_a_completed`
- 当前推进验收点：P2.0-B 图片 API 与 Evidence Inspector

> 本文只冻结技术路线、实施边界和验收方式，不代表已经开始实施。
> 在用户明确授权前，不修改代码、不引入依赖、不执行 P2 实现性实验。

## 1. 当前基线

- S1 研究、证据链和 Workbench 已通过当前有界验收。
- PDF 当前只生成页级文本 `DocumentSegment`，Markdown 当前按标题生成文本段。
- `SourceSnapshot`、`ArtifactRef`、`EvidenceRef` 和 `RetrievalDocument` 已提供文本 lineage 基础。
- LanceDB 当前表记录文本 Chunk，不包含 `modality`、`asset_id` 或图片向量。
- Workbench 当前 Artifact 内容接口只返回 UTF-8 文本，不能直接承载图片预览。
- P2 不修改既有 text-only 检索默认路径；多模态能力未通过回归前，文本路径继续作为稳定入口。

## 2. 目标、主张与非目标

### 2.1 目标

P2 建立一条可审计、可回放、可关闭的图片资产与多模态检索链路：

```text
PDF -> 页面/图片 Artifact -> DocumentAsset -> 父 Chunk lineage
    -> 图片 Evidence 展示 -> 可选图像向量 -> modality-aware retrieval
    -> Evidence/Citation -> 报告引用
```

首个版本必须能够回答：

1. 图片来自哪个文档、SourceSnapshot、页面和页面区域；
2. 图片原始字节、缩略图和抽取 manifest 是否能够按哈希回读；
3. 图片关联了哪些父文本段，无法关联时属于哪类失败；
4. 检索结果使用了哪个模型、索引版本和配置；
5. 最终图片引用是否仍满足现有 Evidence/Citation 闭包。

### 2.2 可验证主张

| 主张 | 比较对象 | 指标 | 证据 |
|---|---|---|---|
| 图片资产可以稳定抽取和回读 | 人工标注 fixture | 资产发现、哈希、页码、bbox、回读率 | fixture manifest、抽取 manifest、Artifact |
| 图片 Evidence 可以被准确复核 | 文本 Evidence 展示路径 | Artifact/页码/bbox 定位正确率 | API 响应、浏览器截图、人工复核表 |
| 跨模态检索能够找到文本检索遗漏的图片证据 | text-only、caption baseline | Recall@k、MRR、Evidence coverage | 固定评估集、原始检索结果、索引 manifest |
| 引入多模态后文本路径不退化 | 冻结 text-only 回归集 | 原有检索与回答指标 | 回归测试与对比报告 |

### 2.3 非目标

- P2.0 不执行 OCR、公式理解、表格结构化或自动 KPI 抽取。
- 不用模型生成的图片描述替代原始图片、图注或定位信息。
- 不引入 GraphRAG、外部托管向量数据库、前端框架迁移、Memory、Skill 或 MCP。
- 不覆盖历史 Artifact、文本索引、Run 或既有验收结果。
- 不把离线图片 embedding 或单个演示案例表述为正式多模态能力。

## 3. 技术选型

### 3.1 PDF 图片抽取

| 方案 | 收益 | 局限 | 决策 |
|---|---|---|---|
| 仅使用 `pypdf` | 复用当前直接依赖 | bbox、inline image、蒙版和复合图处理边界较弱 | 不作为 P2 默认抽取器 |
| PyMuPDF 原图抽取 + 页面区域渲染 | 可同时获得页面图像信息、bbox 和区域渲染 | 需要新增直接依赖并冻结坐标语义 | 推荐进入 P2.0-0 验证 |
| 整页渲染 + CV 分割 | 可覆盖复杂复合图 | 算法和评估复杂，容易产生误分割 | 仅作为后续实验，不进入 P2.0 默认路径 |

推荐路线为确定性混合抽取：

1. 优先提取 PDF 内嵌原始图片字节；
2. 原图无法独立还原或包含蒙版时，渲染对应页面区域；
3. 无法确定图片区域的扫描页只记录 `scanned_page_detected`，P2.0 不执行 OCR；
4. 原图与渲染图必须使用不同的 `asset_kind` 和 `extraction_method`。

当前锁文件中存在 PyMuPDF `1.28.2`，但它来自间接依赖。若 P2.0-0 验证通过，正式实施时必须将其加入项目直接依赖并冻结兼容范围。

### 3.2 图片身份与去重

- `artifact_ref` 按图片字节 SHA-256 寻址，相同字节由 Artifact Store 自动去重。
- `asset_id` 标识图片在文档中的一次出现，不能直接等于图片内容哈希。
- `asset_id` 由文档 ID、页码、标准化 bbox、内容哈希和抽取版本稳定派生。
- 同一图片在不同页面或不同位置出现时保留不同 `asset_id`，并通过 `duplicate_of_asset_id` 关联。
- 重复图片不得静默删除；抽取 manifest 必须同时给出 occurrence count 和 unique content count。

### 3.3 LanceDB 组织

不直接修改或覆盖当前文本表。P2 使用版本化表族：

```text
chunks                  当前文本索引，保持兼容
image_assets_v1         图片向量及图片元数据
multimodal_joint_v1     仅在联合图文模型通过准入后可选建立
```

每个图片索引记录至少包含：

- `asset_id`、`modality=image`；
- `source_snapshot_id`、`parent_chunk_ids`；
- `locator_json`、`artifact_ref`；
- `embedding_model`、`dimensions`、`vector`；
- `extractor_version`、`corpus_hash` 和配置哈希。

不同向量空间的 cosine score 不得直接比较。文本表和图片表分别检索后，默认使用 RRF 或冻结的 rank normalization 进行融合。

### 3.4 Image Embedding

候选路线：

| 路线 | 用途 | 证据边界 |
|---|---|---|
| 联合图文 embedding | 文本查图、图片查文 | P2.1 首选，必须验证模型真实支持两种输入 |
| 图片描述 + 文本 embedding | 低成本 baseline | 描述只用于辅助召回，不得替代图片 Evidence |
| 本地 CLIP 类模型 | 离线 baseline 或显式 fallback | 必须单独标记模型和条件，不得静默降级 |

Provider 准入至少验证：模型标识、输入协议、响应 schema、向量维度、批量上限、超时、成本、原始响应 Artifact 和失败语义。

## 4. 冻结的数据合同

### 4.1 `DocumentAsset`

```text
schema_version
asset_id
document_id
source_snapshot_id
page
asset_kind
artifact_ref
thumbnail_artifact_ref
media_type
content_hash
width_px
height_px
bbox
coordinate_space
page_width
page_height
page_rotation
caption
caption_locator
parent_segment_ids
extraction_method
extraction_status
duplicate_of_asset_id
warnings
```

字段语义：

- `page` 使用 1-based 页码。
- `bbox` 为 `x/y/width/height` 浮点值。
- `coordinate_space` 第一版固定为 `pdf_page_points_top_left`。
- bbox 单位为 PDF point，左上角为原点，并同时记录页面宽高与 rotation。
- `asset_kind` 第一版仅允许 `embedded_image | rendered_region | scanned_page`。
- `extraction_status` 第一版仅允许 `extracted | degraded | failed | duplicate`。
- `caption` 只允许确定性页面文本抽取结果；为空不是错误。
- 正常文本 PDF 的图片按页码关联当前页级 `DocumentSegment`。
- 扫描页或无正文页允许 `parent_segment_ids=[]`，但必须记录 warning。

### 4.2 Manifest

新增两个版本化 schema：

1. `conflux-weave.document-assets.v1`：单个文档的完整资产清单；
2. `conflux-weave.asset-extraction-manifest.v1`：批次级输入、抽取器、配置和统计。

批次 manifest 至少记录：

- 输入 PDF、SourceSnapshot 和内容哈希；
- 抽取器名称、版本、参数和配置哈希；
- 页数、资产出现数、唯一内容数；
- extracted/degraded/failed/duplicate 分类统计；
- 原始图片、缩略图和资产清单 Artifact；
- 开始时间、结束时间和失败详情。

### 4.3 Evidence 兼容

不建立第二套 Citation 体系。现有 `EvidenceRef` 和 API 响应增加向后兼容的可选字段：

```text
modality: text | image = text
asset_id: string | null
artifact_ref: string | null
```

文本 Evidence 字段和默认值保持不变。图片 Evidence 的 `quote` 保存原始图注或空字符串，不能保存未经标记的模型描述。

## 5. 实施阶段与验收

### P2.0-0：Fixture、合同与抽取策略冻结

从真实论文语料中选择至少 6 份 PDF：

1. 正常嵌入图片和图注；
2. 同一图片重复出现；
3. inline image、透明蒙版或特殊色彩空间；
4. 矢量或复合图，需要区域渲染；
5. 扫描页或无可提取文本；
6. 纯文本 PDF 负例。

每份 fixture 记录：

- 文件路径、SHA-256、页数；
- 人工标注的主要图片、页码和 bbox；
- 是否预期获得原始图片字节；
- 允许的降级与失败类别；
- 输出目录和人工复核说明。

验收：

- fixture manifest 可重复生成且输入哈希一致；
- `DocumentAsset` schema、坐标系和稳定 ID 算法通过评审；
- `pypdf`、PyMuPDF 原图抽取和区域渲染完成只读 spike 对比；
- 明确第一版抽取器及其失败边界；
- 未满足上述条件时不得进入 P2.0-A。

### P2.0-A：图片资产与 Lineage

建议新增独立模块 `src/conflux_weave/document_assets.py`，避免继续扩大文本解析模块职责。

处理顺序：

1. 从原始 PDF Artifact 读取并校验字节；
2. 枚举页面图片出现位置；
3. 优先抽取原始图片，必要时渲染区域；
4. 校验媒体类型、尺寸和内容哈希；
5. 生成缩略图；
6. 按页码关联父 `DocumentSegment`；
7. 使用页面邻近文本块提取原始图注；
8. 写入图片 Artifact 和 `document-assets.v1`；
9. 生成批次 manifest，不改变 text-only 索引。

聚焦测试建议：

- `tests/test_document_assets_contract.py`；
- `tests/test_pdf_asset_extraction.py`；
- `tests/test_document_asset_lineage.py`；
- `tests/test_asset_extraction_manifest.py`；
- 现有 document、artifact 和 corpus import 回归。

验收：

- 正常 fixture 中人工标注的主要图片全部找到；
- 成功资产的哈希、页码、bbox、尺寸和 Artifact 回读率为 100%；
- 相同输入重复执行产生相同 `asset_id` 和 manifest 内容；
- 重复图片 occurrence 与 content 去重统计正确；
- 所有漏提取或降级都有明确失败类型；
- 现有文本导入、索引和检索结果不退化。

### P2.0-B：图片 API 与 Evidence Inspector

当前 Artifact 内容接口强制 UTF-8 解码，图片需要增加受限二进制读取路径：

```text
GET /api/v1/library/documents/{document_id}/assets
GET /api/v1/library/assets/{asset_id}
GET /api/v1/library/assets/{asset_id}/content
```

安全与合同要求：

- 只能通过 registry 中登记的 `asset_id` 访问，不能暴露任意本地路径或任意 Artifact ID；
- `/content` 只允许批准的图片 MIME 类型，并设置正确的 `Content-Type`；
- 设置大小上限、inline 响应、缓存头和不可执行内容策略；
- 原图不可显示时仍返回元数据和明确错误，不丢弃 Evidence。

Workbench Evidence Inspector 展示：原图、缩略图、页码、bbox、图注、父 Chunk、SourceSnapshot、抽取方式和 warnings。

验收：

- API 合同、越权读取、损坏 Artifact、超限文件和错误 MIME 测试通过；
- 桌面、移动端和打印模式不破坏现有文本报告；
- 图片引用可从报告定位到 Evidence，再定位到原始 Artifact；
- 浏览器无布局溢出、遮挡和控制台错误。

### P2.1：Image Embedding 与图片索引

新增合同：

```text
ImageEmbeddingPort
ImageEmbeddingRequest
ImageEmbeddingResult
MultimodalIndexRecord
MultimodalRetrievalHit
```

执行要求：

- 每批保存请求、响应、模型、维度、耗时、成本和失败 Artifact；
- 图片资产与向量必须一一对应；
- 临时表完整写入后再原子发布 index manifest；
- 批次失败、数量不一致、维度变化或 Artifact 缺失时不发布；
- 不改变 text-only 默认查询入口。

### P2.2：有限跨模态检索

按以下顺序开放：

1. 文本查询查找图片；
2. 图片查询查找文本；
3. 文本与图片结果 rank fusion；
4. 图片 Evidence 进入 Context Assembly；
5. 图片 Citation 进入报告和 Evidence Inspector。

检索结果必须保留 modality、模型、索引版本、SourceSnapshot、页码、bbox、asset_id 和 Artifact 引用。

### P2.3：固定评估与默认路径裁决

评估集至少包含：

- 10 份真实论文；
- 30 个图文相关查询；
- 10 个无答案查询；
- text-only、caption baseline、joint embedding 三组条件。

拟冻结的准入阈值：

- image Recall@5 `>= 0.80`；
- MRR `>= 0.60`；
- Artifact、页码和 bbox 定位正确率 `100%`；
- Citation/Evidence closure `100%`；
- 无答案误召回率 `<= 0.10`；
- 冻结 text-only 回归集不得退化。

这些阈值必须在 P2.1 正式编码前冻结，不得根据实验结果事后修改。

## 6. 状态、失败与停止条件

失败分类至少包括：

- `embedded_image_unavailable`；
- `bbox_unavailable`；
- `render_failed`；
- `unsupported_color_space`；
- `duplicate_content`；
- `caption_not_found`；
- `parent_segment_missing`；
- `scanned_page_detected`；
- `artifact_integrity_failed`；
- `embedding_provider_failed`；
- `embedding_dimension_mismatch`；
- `index_publish_failed`。

停止进入下一阶段的条件：

- fixture 或输入哈希未冻结；
- 成功资产无法按哈希回读；
- 正常文本 PDF 的页码或父 Chunk lineage 不闭合；
- 相同输入不能稳定产生相同资产身份；
- 失败被静默忽略或使用模型描述掩盖；
- 新增能力导致现有 text-only 回归失败；
- 图片索引无法做到失败不发布。

## 7. 回滚与恢复

- 使用 `CONFLUX_WEAVE_MULTIMODAL_ENABLED=false` 作为总关闭入口。
- 图片抽取、图片索引和跨模态检索分别设置能力开关，不共享隐式 fallback。
- 不原地覆盖现有文本表；图片索引使用新表和新 manifest。
- 索引构建失败时保留失败批次 Artifact，但不更新已发布 manifest。
- 旧版本读取器忽略新增 registry 和 Evidence 可选字段，保持向后兼容。
- API、Workbench 或 Provider 失败时可以关闭对应阶段并继续使用 text-only RAG。

## 8. 预期模块落点

| 模块 | 计划变化 |
|---|---|
| `documents.py` | 保留文本导入；只增加必要的可选资产引用，不承载完整抽取实现 |
| `document_assets.py` | 新增 DocumentAsset、抽取器、稳定 ID、manifest 和 lineage |
| `evidence/contracts.py` | 增加向后兼容的图片 Evidence 可选字段 |
| `indexing.py` | 新增图片表发布、版本 manifest 和过滤查询，不覆盖文本表 |
| `retrieval.py` | 新增多模态结果合同和 rank fusion，保留现有文本合同 |
| `provider.py` 或独立 adapter | 增加 ImageEmbeddingPort 实现与 Provider 准入 |
| `api_contracts.py` | 增加资产元数据和图片 Evidence 响应 |
| `server.py` | 增加受限图片资产 API，不复用 UTF-8 文本内容接口 |
| Workbench Evidence Inspector | 增加图片预览、定位、错误和响应式状态 |

## 9. 证据与交付物

每个阶段保存：

- 输入文件及 SHA-256；
- schema 和配置版本；
- 抽取、Provider 和索引 manifest；
- 原始图片、缩略图、请求和响应 Artifact；
- 失败案例和错误分类；
- 聚焦测试、回归测试和浏览器验证结果；
- 评估原始结果、汇总表和人工复核记录。

测试通过只能证明对应机制，不自动证明真实多模态能力。只有固定真实案例、真实 Provider、真实索引和完整 Evidence/Citation 流程通过后，才能标记相应能力为 `validated_live`。
