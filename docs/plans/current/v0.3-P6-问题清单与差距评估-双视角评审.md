- 日期：2026-09-13（基线：提交 `9b62388`，全量回归 `599 passed`）
- 性质：**冻结 P6 计划前的讨论输入**（治理规则 3：未经采纳的讨论留在活跃计划）。本文不是实施方案，不含验收门；P6 计划冻结时应逐项消费本清单并给出取舍。

## 0. 总体定位（先说强的）

验证纪律是本项目的独特优势，方向不应丢失：冻结裁决与密封 Run、`code_revision` 幂等键、HITL 物理核准、无降级确定性兜底、Evidence/Artifact 全程可审计——这些实践超过多数业界同类项目。缺陷集中在**执行架构、记忆召回、工具沙箱、运维外围**，均有清晰地基可改，非重构级障碍。

成熟度打分（专家视角）：验证纪律 9/10，执行架构 5/10，记忆 4/10，工具生态 6/10，可运维性 3/10。

## A. 产品功能缺口（用户视角）

| 编号 | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| A1 | **成果导出缺失**：报告/笔记零导出端点（无 Markdown 文件、PDF/Word、BibTeX） | `server.py` 无任何 export/download 路由 | 研究产出锁死在库内，写论文时引用 `[1] 标题[web] URL` 无法变参考文献条目；"最痛的一公里" |
| A2 | **数据只进不出**：对话/Run/文档无删除、归档、重命名；全后端仅 2 个 DELETE（memories、mcp/servers）；conversations 有 `archived_at` 字段未暴露 API | `chat.py:184`（archived_at 已建未用） | 长期使用后列表不可管理 |
| A3 | **无全局搜索**：Omnibox 只做意图路由，不能跨笔记/对话/报告/文献搜关键词 | 无对应端点 | "记得在哪见过 X"只能逐区翻 |
| A4 | **长任务完成无通知**：深度研究单次 ~872s，SSE 仅页面存活有效，无浏览器通知/完成提示 | `server.py:1399-1425` | 被动等待，体验硬伤 |
| A5 | **var/ 无备份迁移工具**：唯一权威数据（SQLite+LanceDB+artifacts）无一键备份/恢复/导入 | README 仅声明"不得提交" | 换机/误删即灾难 |
| A6 | **Skill 无自建流**：内置 3 个，`SkillRegistry.register_skill` 存在但无前端创作流，不能像 MCP 那样从本地文件加载 | `skills/registry.py:171` | Skill 工坊是"展厅"非"工坊" |
| A7 | **PDF 阅读流断裂**：不能在 PDF 上划词提问/就地记笔记并自动带页码引用；NoteStudio 与资料库是两个世界 | 无对应端点/交互 | 研读最自然入口缺失 |

## C. 架构与执行（专家视角）

| 编号 | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| C1 | **单进程模型是根本天花板**：API、Worker（250ms 轮询 `work_once`）、DAG 并发（进程内 `asyncio.Semaphore(3)`）、事件广播（进程内 `asyncio.Queue`，QueueFull 丢弃）全部绑定一个 Python 进程；uvicorn workers=1 | `server.py:200-227`、`dag_scheduler.py:97`、`event_bus.py:96-101` | 长 Run 与 API 抢事件循环；进程崩溃执行现场归零；无法水平扩展。队列语义已藏在 SQLite 表（tasks/leases），缺"当真队列用" |
| C2 | **恢复是记账式而非工作流引擎式**：冻结粒度 = research batch；unknown outcome 人工恢复；individual-call recovery incomplete；无 step 级 checkpoint/自动重试/续跑 | S1 记录；`sqlite_leases.py` 有 lease 雏形 | 严谨但不可运维；成熟形态 = Temporal 式 durable execution |
| C3 | **Provider 层同步 urllib**：`urlopen` + 线程池；无连接池/HTTP2/**token 流式**（chat 全量阻塞返回）；有 retryable 分类（5xx/429）但无多 Provider 故障转移链、熔断、成本熔断执行点 | `provider.py:118,227-334` | RAG 问答 10-30s 白屏是用户可感成熟度硬伤；投入小体感提升最大 |
| C4 | **Provider 合同靠 prompt-schema 解析而非结构化解码**：S1.6 一系列密封失败（`claims` vs `assessments` 根等）即此边界脆弱性；已用 canary + 显式 schema 修补 | S1.6-D/E/F 记录 | 对便宜模型天然高 fail 率；业界用原生 function calling / JSON Schema constrained decoding 在解码层消灭 |

## D. 记忆机制

| 编号 | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| D1 | **召回纯 recency**：查询即 `ORDER BY updated_at DESC, created_at DESC LIMIT ?` 的 SQL，无语义召回——系统有 LanceDB/embedding 管道却未接记忆 | `memory_store.py:304` | 记忆量上百后"该想起的想不起来"；最讽刺的缺口 |
| D2 | **无衰减/使用反馈/遗忘**：recalled 无用不降权，无 TTL | 同上 | 记忆库只增不减 |
| D3 | **无情景/程序性记忆**：过往 Run 轨迹不复用为经验，成功模式不沉淀为 Skill（Skill 全靠人工预置） | 无对应机制 | 记忆完成度 ~40%，提取侧（启发式+模型候选+HITL+L0/L1 ≤400 token 注入硬上限）已达业界前列 |

## E. 工具调用

| 编号 | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| E1 | **无沙箱计算工具**：全系统无 REPL/Jupyter/容器执行环境 | 无对应实现 | 研究 Agent 无计算能力，数据分析靠模型心算；与 Claude Code / Deep Research 类产品的本质能力差 |
| E2 | **无工具权限分级**：MCP server 挂上即全量可用；无 per-run 白名单、参数级审批、危险操作 consent（补丁核准的 HITL 未推广到通用工具面） | `mcp/servers` 端点语义 | 投放市场前必须项 |
| E3 | **MCP 子进程管理薄**：stdio 子进程健康检查/崩溃重启/超时杀灭未实现（以持久化+发现为主） | `MCPServerManager` | 长跑会话可靠性 |
| E4 | **web 内容无注入隔离**：GPT Researcher 抓取内容直入报告管线，有"未核验"标注但无提示注入清洗/隔离层 | W3 证据桥合同 | 单机可接受，市场化必须项 |
