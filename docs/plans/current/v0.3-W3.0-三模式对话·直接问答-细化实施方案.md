# Conflux-Weave v0.3 W3.0 三模式对话·模式 A（直接问答）细化实施方案

三模式回答架构（用户确认）的第一片。本片交付：直接问答模式 + 独立对话持久化 +
前端三模式切换。W3.1（知识库问答）、W3.2（深度研究引擎，GPT Researcher 证据桥）后置。

## 1. 模式定义

| 模式 | 引擎 | 证据 | 产物 | 存储 |
| --- | --- | --- | --- | --- |
| A 直接问答（本片） | 裸 LLM（qwen），问题原样发送 + 同会话近 8 条上下文 | 无（UI 标注"模型知识（未核验）"） | 对话消息 | chat_messages 表 |
| B 知识库问答（W3.1） | 本地 Hybrid 检索 Top-k → 一次成文 | 内联 chunk 引用，不做 Claim 原子化/验证 | 对话消息 + 轻量检索工件 | 同上 |
| C 深度研究（W3.2） | GPT Researcher（网络+本地混合）+ 证据桥 + 现有 ③-⑥⑨ 链 | 完整台账（Snapshot/Evidence/Claim/Citation） | 完整 v2 报告 + manifest | durable Run 全套 |

A/B 为轻路径：不创建 durable Run、无预算/恢复语义、不默认生成报告（用户决策）。
C 为重路径：GPT Researcher 仅承担发现与聚合（原 ①② 层），Claim 验证/引用闭合/
审计/确定性兜底不变；其 report 字符串仅作第二视图存档，Delivery 仍由快照原文生成。

## 2. 本片实现

- `conflux_weave/chat.py`：`ChatService`（direct_answer/history/conversation）；
  `chat_messages` 表（message_id/conversation_id/role/mode/content/created_at，
  独立 `CREATE TABLE IF NOT EXISTS`，不进 runtime 迁移体系——对话记录不是 Run 状态）。
- API：`POST /api/v1/chat`（同步端点，线程池执行 LLM 调用；未配置 Provider 返回
  503 provider_not_configured）、`GET /api/v1/chat/messages?limit=`（未配置返回空集）。
- Provider 调用仍经 `OpenAICompatibleChatAdapter` → 请求/响应照常 Artifact 存证
  （内部审计用，不是交付物）。
- 前端：模式单选改为 直接问答（默认）/ 知识库问答（disabled，W3.1）/ 深度研究
  （沿用现有 verified-research POST，W3.2 替换引擎）；直接问答渲染为
  "直接问答 · 模型知识（未核验）"消息；"新对话"重置会话 ID；挂载时加载最近
  20 条对话记录。
- `code_revision` 进入 durable 幂等键（同代码去重、代码变更重跑）。

## 3. 决策记录

- 对话记录不进 runtime 迁移体系：聊天不是权威 Run 状态，独立轻表降低耦合；
  代价是两套 schema 管理，已用表名前缀与索引隔离。
- Manager 模式从对话入口移除，仍可经研究视图发起；C 引擎上线后对话入口只保留
  三模式，避免四选项的认知负担。
- 直接问答的 Provider 调用保留 Artifact 存证：对话虽无报告，但计费调用仍可审计。
