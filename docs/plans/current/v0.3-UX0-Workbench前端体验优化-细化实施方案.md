# Conflux-Weave v0.3 UX-0 Workbench 前端体验优化细化实施方案

> 状态：`ready_pending_ux0_entry`
>
> 顺序：S1 Final Closure -> UX-0 -> P2.0 图片资产与 lineage
>
> S1 Final Closure 已于 2026-08-27 经协议负责人签署。本方案冻结不等于授权实施；
> 用户明确进入 UX-0 后才开始修改前端。

## 1. 可行性结论

可行，并且应位于 S1 与 P2 之间。当前 Workbench 是 FastAPI 同源提供的 Vanilla
HTML/CSS/JavaScript，约 226/296/483 行，无外部 CDN 或前端构建链依赖。Run 列表、任务
创建、SSE 状态、Delivery、Evidence、恢复动作和 follow-up 已有稳定 DOM/API 边界，适合
在不改变 Runtime 与 Evidence 语义的前提下做一次有界体验重构。

先做 UX-0 的原因不是追求视觉翻新，而是让现有 P1 能力形成稳定、可重复使用的研究工作台
界面，再承载 P2 的图片资产、预览与跨模态结果。若先加入图片检索，当前结果区、证据弹窗和
运行摘要会同时承担新增信息，后续改信息架构的返工和回归面更大。

## 2. 目标与成功标准

目标用户是反复执行论文发现、单 Agent、Manager、追问和证据复核的个人研究者。界面应
安静、紧凑、可扫描，优先支持运行状态判断、结果阅读、证据核对和恢复决策。

成功标准：

1. 四类现有任务可创建，历史 Run 可刷新、重开、追问、重新研究、取消或处理未知结果。
2. 用户在首屏能区分 Run 状态、Delivery disposition、证据闭合、语料范围和预算边界。
3. 结果、Evidence、limitations/recovery 和活动轨迹具有清晰层级，不依赖说明性教学文案。
4. `1440x900`、`1024x768`、`768x1024`、`390x844` 和 `320x568` 无非预期重叠或横向溢出；
   200% zoom 仍可完成核心操作。
5. 键盘可完成导航、对话框、tab、Evidence 查看和主要命令；焦点可见且关闭后返回触发点。
6. 无外部运行时资源、零控制台错误、文本 API 合同与现有 Runtime 状态语义不变。

## 3. 冻结范围

### 3.1 信息架构

- 左侧历史区支持快速扫描任务类型、标题、时间、状态与当前选择。
- 主工作区保持 Run 为中心，顶部只呈现问题、状态和高频命令。
- 执行模式、语料、证据状态、token/tool/retrieval 与费用边界形成紧凑摘要带。
- 结果、Evidence 和运行动态使用明确视图切换；桌面 Evidence 可使用检查器侧栏，移动端
  使用全屏 sheet/dialog，不把重复卡片嵌套在卡片中。
- limitations、unmet criteria、errors 和 recovery actions 按语义分组，不合并成模糊警告。

### 3.2 交互与状态

- 冻结 `empty/loading/queued/working/partial/complete/no_answer/needs_attention/failed/
  cancelling/cancelled/expired` 的显示矩阵和允许动作。
- 新建任务模式使用 segmented control；数值使用原生 number input/stepper；二元设置使用
  checkbox/toggle；命令按钮只承载明确动作。
- 刷新、关闭、新建等熟悉命令使用本地 Lucide 图标子集并提供 tooltip/accessible name；
  不引入 CDN，需记录 vendored 版本和许可证。
- 所有 mutation 显示进行中、成功、失败和可恢复状态，防止重复提交。
- 保留 SSE 游标、重连和 persisted history 语义，不用前端临时状态冒充 Runtime 状态。

### 3.3 视觉系统

- 建立有限的颜色、间距、字体、边框、focus ring、状态色和层级 token。
- 保持工作型界面，避免营销 hero、装饰性渐变、悬浮页面卡片和单一色系铺满。
- 固定工具栏、图标按钮、摘要单元、tab 和 Evidence locator 的响应式尺寸，动态内容不得
  推挤导致布局跳动。
- 标题尺度服从容器，长问题、Artifact ID、SourceSnapshot 和 locator 必须安全换行。

### 3.4 为 P2 预留但不实现

- Evidence 检查器允许未来增加 `modality=image`、图片预览、页码与区域定位槽位。
- 预留是布局插槽和 view-model 边界，不新增图片字段、虚构缩略图或复制 Evidence 数据。
- 文本 Evidence 仍是唯一已实现路径，P2 未通过前不得显示不可用的多模态入口。

## 4. 非目标

- 不修改 Task/Run/Step/Delivery、Artifact、Evidence、Citation 或预算权威语义。
- 不修改现有 API 路径、SSE 协议、SQLite schema、Provider 或 Agent workflow。
- 不迁移到 React/Vue/Svelte，不引入通用组件库或前端构建系统。
- 不实现 PDF 图片抽取、OCR、ImageEmbeddingPort、图文检索或 P2 LanceDB schema。
- 不重跑 S1 Provider live matrix，不借视觉变化声明研究质量或 Agent 收益。

## 5. 分阶段执行

### UX-0.0 基线与设计冻结

- 用 persisted fixture 和至少一个真实历史 Run 保存桌面、平板、移动端截图与 DOM 状态。
- 盘点所有 Run 状态、任务模式、命令、空态、错误态和 Evidence 字段。
- 形成页面信息架构、状态矩阵、关键 workflow 和视觉 token 草案。

验收：状态与操作无遗漏；设计不要求新增后端字段；协议负责人批准进入实现。

### UX-0.1 结构与视觉基础

- 重组 Workbench DOM 区域、响应式 grid、导航、toolbar、tabs 和 Evidence inspector。
- 引入本地设计 token 与 Lucide 图标子集，保留渐进增强和原生 dialog。
- 保持同源静态文件交付，无外部网络依赖。

验收：既有 DOM/API 合同测试更新并通过；主要页面在五个 viewport 无溢出。

### UX-0.2 工作流与完整状态

- 完成任务创建、历史选择、刷新、取消、追问、rerun、未知结果决策和 toast/focus 管理。
- 为所有状态提供确定性 fixture，检查允许动作和禁止动作。
- 优化结果、Citation/Evidence、limitations 和 activity 的扫描与定位效率。

验收：所有现有 workflow 可完成；键盘路径、焦点返回、错误恢复与重复提交保护通过。

### UX-0.3 浏览器验收与冻结

- Playwright 运行 desktop/tablet/mobile/200% zoom 截图、overflow、console 和关键交互检查。
- 使用 persisted real Run 验证刷新与重开，不创建无必要的付费 Provider Run。
- 执行聚焦前端/API 测试、全量 pytest 和 package build，冻结截图与 summary hash。

验收：成功标准全部满足，文本 RAG/Agent 路径无行为回归，UX-0 标记
`validated_browser_and_regression`。

## 6. 验收材料

- `var/acceptance/v0.3-ux0/baseline/`：改造前截图、状态盘点和浏览器环境。
- `var/acceptance/v0.3-ux0/final/`：最终 viewport 截图、DOM/overflow/console/交互 summary。
- 版本化 deterministic fixture：覆盖全部 Run/Delivery/error 状态，不包含 Provider 成功伪证。
- 测试记录：聚焦 Workbench/API、全量 pytest、sdist/wheel build。
- 状态文档：修改 revision、证据 hash、未覆盖浏览器与已知限制。

## 7. 风险、停止条件与回滚

| 风险或条件 | 处理 |
|---|---|
| 设计要求新增后端字段或改变状态语义 | 停止 UX-0，单独形成 API/ADR 决策 |
| Vanilla 文件继续增长导致状态耦合不可测 | 先拆分本地 ES modules；仍不引入框架 |
| 图标依赖要求 CDN 或运行时外网 | 停止依赖引入，改用本地 vendored 子集 |
| 移动端信息密度与核心操作冲突 | 保留结果优先，Evidence/Activity 使用独立视图，不压缩成不可读布局 |
| 浏览器环境不可用 | 保留静态/合同测试，但不得标记浏览器验收通过 |
| UI 修改影响 Runtime/API 行为 | 回滚前端提交，后端保持不变 |

前端修改按 UX-0.x 独立提交；旧静态文件可由 Git revision 恢复。运行证据只追加，不覆盖
S1 的 `browser-s15b` 材料。
