## 0. 这一份方案回答的问题

1. 工作台如何从"单一 Run 视图"扩展为多分区而不用改变冻结的视觉语言？
2. 用户如何一眼知道系统有什么功能、怎么用（总览工作台）？
3. 统一对话入口在 P4 之前以什么形态存在（可用雏形而非占位）？
4. 各项配置如何修改（配置中心 v1）？
5. 未来分区（文档/项目/知识/Skill-MCP/记忆）如何以最小成本接入？

## 1. 用户决策记录（2026-08-28 批准）

| 决策点 | 决定 |
|---|---|
| 分区导航位置 | 顶栏文字 Tab（总览/对话/研究/设置），非研究分区隐藏左列、主区全宽 |
| 统一对话入口形态 | 可用雏形：提问即创建真实研究 Run，SSE 实时动态 + 对话流交付渲染；P4 统一对话路由成熟后仅替换后端提交入口，UI 合同不变 |
| 未上线分区（文档/项目/知识） | 暂不在导航显示；功能上线时再加入（延续"宁愿没有也不许假数据/无功能元素"原则） |

## 2. 范围

### 2.1 交付

1. **分区导航与 hash 路由**：`#/overview`（默认）、`#/chat`、`#/research`、
   `#/research/<run_id>`、`#/settings`。选中 Run 时地址静默同步
   （`history.replaceState`）；刷新/分享深链后停留在原视图。视图注册表
   `VIEWS`（`modules/router.js`）：新分区 = 新增模块 + 注册一项。
2. **总览工作台**：快速开始（三步使用说明 + 新建研究/去对话）；
   系统状态（`/api/v1/health/ready` 三项 checks 的真实数据与恢复建议）；
   最近研究（5 条真实 Run，点击深链）。Provider 未就绪时顶部出现
   引导条直达设置。Knowledge/Projects 无真实数据不显示。
3. **统一对话入口 v1**：提交即 `POST /api/v1/tasks/verified-research`
   （单 Agent/Manager 可切）；用户消息 + 实时状态行（SSE 事件与
   进度/token）；终态渲染交付正文（与 Run 视图同一渲染规则）、证据数、
   限制/未满足摘要与状态徽章；动作：继续追问（`/follow-up`，仅 verified
   家族）、在研究中打开完整 Run。进入时加载最近 verified 家族 Run 为
   只读历史线程；追问上下文以 chip 呈现并创建新的独立 Run。
4. **设置视图**：模型服务表单（base_url/API Key/Chat/Embedding/Reranker，
   API Key 密文输入、留空保持不变、保存后回显尾 4 位 hint）；
   测试连接；系统检查；数据目录（只读）；运行预算（只读，取最近 Run
   实际上限）；关于。
5. **配置 API（新增 3 条，现有 16 条零改动）**：
   - `GET /api/v1/config`：Provider 脱敏视图（`api_key_configured` +
     尾 4 位 hint，密钥本体永不返回）+ `provider_active` + 只读数据目录；
   - `PUT /api/v1/config/provider`：HTTPS 校验、空 Key=保留现值、
     原子写入 `.env`（保留注释与无关行），返回 `requires_restart: true`；
   - `POST /api/v1/config/provider/test`：复用 `OpenAICompatibleChatAdapter`
     发起 1 次小输出调用，返回 ok/latency/失败消息（消息不含密钥）。
   新增 `src/conflux_weave/config_store.py`：dotenv 五键读写、
   进程环境变量优先读取、写入后回显以 dotenv 文件为准。
6. **配置持久化语义**：Provider 配置在进程启动时读取一次（现状合同），
   保存后需重启 `conflux-weave serve` 生效；UI 明示该边界，本期不实现热重载。

### 2.2 非目标

- 不引入框架/组件库/CDN；不改 16 条既有端点、SSE 协议、RunStatus 等
  枚举、SQLite schema、Provider/Orchestrator/Agent 行为路径。
- 不改研究视图既有行为与视觉（状态×动作矩阵、Inspector、对话框原样）。
- 不做配置热重载；不做 Knowledge/Projects 假数据；不做 P2 图像/OCR 入口；
  不实现预算修改（预算中心随 P4）。

## 3. 实现要点

### 3.1 前端模块化

- `workbench/modules/shared.js`：`api`/`showToast`/`formatDate`/
  `renderAnswer`/`stateLabels`/`familyLabels`/`modeLabels`/`renderChecks`。
- `workbench/modules/router.js`：hash 解析、`registerView`、分区切换
  （`hidden` 与 `aria-current`）、`.app-shell[data-section]`。
- `workbench/modules/{overview,chat,settings}.js`：三个视图模块，
  `mount/unmount/onParam` 生命周期；对话视图 unmount 关闭全部 SSE watch。
- `app.js` 保留为研究视图模块 + 入口：全部既有测试锚点字符串原地保留；
  研究逻辑逐行不变（新增：选中 Run 时 `replaceHash` 同步地址、
  创建 Run 后 `navigate` 跨分区跳转）。
- `index.html`：顶栏 `<nav class="section-nav">`、三个新 `<section>`、
  缓存版本 `?v=v0.3-ux1`；全部既有 ID 保留。

### 3.2 对话 SSE 客户端

对话视图自带精简 SSE 客户端（与 Run 视图同协议：`after` 游标去重、
500ms 断线重连、终态关闭），不抽取 app.js 既有实现以保护其测试锚点；
后续如需合并再单独评估。

### 3.3 设计语言

全部新界面沿用苔原 Moss token、衬线标题、hairline、色点状态、骨架屏、
底部居中 Toast；不新增颜色 token；印刷细节（中点分隔、tnum、locator
chip、克制滚动条、reduced-motion 降级、@media print）同步覆盖新分区。

## 5. 边界声明

UX-1 是交互机制与信息架构交付：不声明研究能力提升、不证明配置热重载、
不引入统一对话路由（仍是 P4）、不涉及多模态或 Memory。对话入口当前
提交的是既有 verified research 能力，意图识别/多 Agent 调度/记忆仍属
P4/P5。Firefox/WebKit 与原生屏幕阅读器验证仍未覆盖（与 UX-0 相同）。
