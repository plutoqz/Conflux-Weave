## 1. 当前判断

当前系统已经达到研究型 Agent Workbench 的第一阶段成熟度：

- 研究结果可导出；
- 对话、Run、文档支持生命周期管理；
- 长任务具备阶段反馈、SSE 重放和通知；
- 记忆具备真实 embedding 召回、作用域隔离和确定性降级；
- 计算工具具备单机研究工具级沙箱；
- API 与 Worker 已能分离；
- `retrieve/deliver` 外层已经具备 checkpoint 和恢复能力。

但当前还没有达到成熟 Agent 平台的完整形态：

- C2 内部阶段尚未统一纳入 durable checkpoint；
- Provider 故障转移和结构化输出容错不足；
- MCP 和计算工具还缺少生产级治理；
- 记忆缺少完整生命周期；
- 全局搜索、PDF 研读联动和备份迁移尚未形成闭环；
- 多租户、鉴权、监控和容量模型仍未建设。

因此，当前剩余工作不能全部视为验证任务：

```text
已实现能力的真实运行确认：验证任务
未实现能力和架构短板：继续开发任务
```

## 4. P7-A：研究资料与知识组织能力

这是下一阶段最值得优先实现的用户功能批。

### A1 全局搜索

#### 目标

提供统一入口搜索：

- 对话；
- 研究报告；
- 笔记；
- 文档；
- 论文；
- Evidence；
- 项目文件。

#### 推荐实现

```text
结构化过滤
→ SQLite FTS/BM25
→ 可选语义召回
→ 类型/时间/项目重排
→ 原文定位跳转
```

SQLite 作为元数据和文本搜索权威；LanceDB 只承担语义候选召回，不复制对象生命周期。

#### 最小 API

```text
GET /api/v1/search?q=&types=&project_id=&from=&to=&limit=
GET /api/v1/search/{result_id}/locate
```

#### 验收标准

- 一个查询可跨多个对象类型返回结果；
- 结果带类型、标题、更新时间和匹配原因；
- 可以跳到对话消息、笔记段落、文档页码或 Evidence；
- 归档和软删除对象按筛选规则处理；
- 无结果时不调用生成模型；
- 结果不跨项目泄漏。

### A2 PDF 研读联动

#### 最小闭环

```text
打开 PDF
→ 选择文本或图表
→ 提问/生成笔记
→ 自动附带 document_id、页码、segment_id
→ 生成 NotePatch 或研究任务
→ 从笔记跳回原文定位
```

#### 验收标准

- 文本选择带页码和 segment 定位；
- 图表选择带 asset_id 和父 Chunk；
- 生成的笔记保留原始引用；
- 笔记引用可以回到 PDF；
- 无定位信息时明确标记，而不是伪造页码；
- 失败时保留用户选中的原文。

### A3 备份、恢复与迁移

#### 首批范围

- SQLite；
- LanceDB；
- Artifact Store；
- source-cache 中的必要元数据；
- 配置模板，不包含密钥明文。

#### 备份包内容

```text
backup-manifest.json
runtime.sqlite3
lancedb/
artifacts/
config-template.env
```

#### 验收标准

- 一键生成备份；
- 备份前执行数据库一致性检查；
- 恢复前验证版本和路径；
- 恢复后 SQLite、向量索引和 Artifact 数量一致；
- 随机抽样 Artifact 可读；
- 恢复失败不覆盖原数据；
- 备份结果不包含 Provider key。

### B2 衰减与有效期召回加权（已交付）

混合记忆召回（`MemoryRecallService.recall`）已支持生命周期治理：

- **过期过滤**：`expires_at <= now` 的记忆自动在召回候选集过滤剔除；
- **置顶优先**：`is_pinned=True` 的记忆获得 `+0.50` 优先加权，豁免相关性门槛并在配额内置顶；
- **用户反馈打权**：`user_feedback=1` 获得 `+0.25` 增益（reason 标注 `用户赞同`），`user_feedback=-1` 获得 `-0.35` 惩罚（reason 标注 `用户降权`）；
- **综合公式**：
  ```text
  final_score = base_score + (0.50 if is_pinned else 0.0) + (0.25 if fb > 0 else (-0.35 if fb < 0 else 0.0))
  ```
- **测试覆盖**：`tests/test_p7_b_memory_lifecycle.py` 6 项专项测试全部通过。


- 失败原因和 Provider 能力缓存。

所有路由决策写入 Run：

```text
provider
model
reason
fallback_chain
latency
usage
```

## 7. P7-D：工具生态与扩展能力

### D1 计算工具升级

当前 bootstrap 沙箱只适合单机研究工具。若要运行不可信代码，需要 OS 级隔离：

- 容器；
- Windows Job Object；
- 受限 Token；
- 文件系统隔离；
- 网络命名空间；
- CPU/内存/进程/文件数配额；
- 独立 Worker；
- 资源超限强制终止。

升级前必须明确威胁模型，不能把当前方案宣传为安全执行环境。

### D2 MCP 运行时治理

补充：

- 子进程健康检查；
- 崩溃重启；
- 调用超时；
- 工具 Schema 漂移检测；
- 工具版本和能力声明；
- 单工具限流；
- 失败熔断；
- 返回内容隔离；
- 外部写操作 HITL。

### D3 Skill 本地创建与版本化

第一批支持：

- Markdown/YAML 创建；
- 输入 Schema 编辑；
- 默认预算设置；
- 本地测试运行；
- 启用/停用；
- 版本号；
- 运行记录；
- 回滚。

暂不建设公开 Skill 市场。

### D4 统一 ToolResult

Skill、MCP、Compute 统一输出：

```text
ToolCall
ToolResult
PermissionDecision
Artifact
Evidence
Usage
```

Agent 只能引用状态明确、来源可追溯的工具结果。

## 8. P7-E：市场化部署能力

只有在确定要公网或多人部署时启动。

优先顺序：

```text
E1 鉴权与租户隔离
E2 Provider key 安全存储
E3 备份与恢复演练
E4 OTel trace、metrics、告警
E5 并发压测与 soak
E6 灰度、回滚和版本迁移
E7 ToS、频控和数据合规
```

### 上线阻塞标准

未完成以下项目，不应宣称可公网部署：

- API 鉴权；
- Artifact 访问控制；
- Provider key 不落日志；
- 备份可恢复；
- 队列积压可观测；
- Worker 崩溃可接管；
- 基础并发容量已知；
- 数据删除和保留策略明确。

## 9. 推荐 Gate 顺序

```text
Gate V1  A5/B1/C1/C2/W3 真实验证
Gate V2  状态文档和证据同步
Gate A1  全局搜索
Gate A2  PDF 研读联动
Gate A3  备份恢复迁移
Gate B1  记忆治理和反馈
Gate B2  记忆衰减与程序性记忆

Gate C2  Provider failover 与结构化解码
Gate D1  MCP/Skill 生命周期治理
Gate E1  公网部署安全和运维
```

每个 Gate 必须记录：

- 修改文件；
- 代码版本；
- 测试命令；
- 实际测试结果；
- 真实 Run 或浏览器证据；
- 失败案例；
- 未覆盖场景；
- 是否进入下一 Gate。

## 11. 最终边界

当前系统已经适合继续作为个人研究型 Agent Workbench 使用和真实验证，但不应宣称已经具备：

- 完整七阶段 durable execution；
- 不可信代码安全执行；
- 多 Provider 生产级故障转移；
- 多用户 SaaS 能力；
- 公网部署级安全和运维成熟度。

后续路线的核心判断是：

```text
先完成已实现能力的真实验证，
再补研究者高频缺失功能，
随后统一执行、记忆和工具治理，
最后建设市场化基础设施。
```
