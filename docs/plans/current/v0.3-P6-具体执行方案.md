# Conflux-Weave v0.3 P6 · 具体执行方案

- 日期：2026-09-12
- 性质：P6 计划讨论稿，供后续冻结范围和验收门使用
- 来源：`v0.3-P6-问题清单与差距评估-双视角评审.md`
- 本文不纳入：冻结实验哈希功能必要性评估

## 1. P6 总目标

将当前系统从“功能已经实现、证据较完整的研究型工作台”推进到：

- 研究结果可以顺畅导出；
- 对话、Run、文档可管理；
- 长任务过程可见、结果可追踪；
- 记忆能够被准确召回；
- Agent 能在受控环境中执行计算；
- 任务失败后可以恢复；
- 不破坏已有 Evidence、Artifact、HITL 和确定性兜底机制。

总体顺序：

```text
P6-A 研究产出与工作台闭环
P6-B Agent 能力增强
P6-C 执行可靠性升级
P6-D 市场化基础设施
```

P6-A 至 P6-C 属于本轮主体，P6-D 另行立项。除非近期明确公网部署，不提前扩大到多租户和完整商业化基础设施。

## 2. 执行原则

1. 每个工作包先确认当前实现、数据结构、运行入口和工作树状态。
2. 只修改当前工作包涉及的模块，不进行无关重构。
3. 保留现有失败记录、Evidence、Artifact 和 Run 关系。
4. 离线测试、回放验证、真实服务验证和浏览器验证分开记录。
5. 每个验收门都记录实际结果、失败案例、未覆盖边界和后续风险。
6. 不以测试数量增加代替真实能力验证。
7. 不把导出文件、缓存或评测文件作为 Runtime 权威状态源。

## 3. P6-A：研究产出与工作台闭环

### A0 当前基线确认

**目标**：在代码修改前确认当前真实状态。

检查：

- 当前分支、工作树和服务进程；
- API、React 前端和 Worker 的启动方式；
- 当前全量回归结果；
- W3.2/W3.5 深度研究真实验收状态；
- P2 图文混合默认路径的运行状态；
- `var/` 中报告、笔记、Evidence 和 Artifact 的数据结构。

交付：

- 当前 API 路由清单；
- 当前前端关键用户路径清单；
- 一组真实报告、笔记、对话和 Run 验收样本；
- 基线测试和服务状态记录。

验收门：

- 明确当前系统能导出什么、能删除什么、能恢复什么；
- 明确长任务状态的查询和事件来源；
- 不修改代码即可复现现有主流程。

### A1 成果导出

#### 首批范围

首批只实现：

1. Markdown；
2. BibTeX；
3. JSON/ZIP 证据包。

PDF/Word 高保真导出不纳入第一批。

#### 导出对象

- 深度研究报告；
- 知识库问答结果；
- DocumentAgent 笔记；
- 单个 Evidence；
- Run 的完整证据包。

#### 必须保留的信息

- 标题和正文；
- 引用编号；
- 来源标题和 URL；
- 页码或其他定位信息；
- Evidence ID；
- 生成时间；
- Run ID；
- `code_revision`；
- 失败、部分成功和未核验状态。

#### 实施步骤

1. 抽象统一的 `ExportDocument` 数据结构。
2. 实现 Markdown renderer。
3. 从 Citation/Evidence 生成 BibTeX。
4. 实现 JSON/ZIP evidence bundle。
5. 增加导出 API：
   - `GET /api/v1/runs/{id}/export?format=markdown`
   - `GET /api/v1/runs/{id}/export?format=bibtex`
   - `GET /api/v1/runs/{id}/export?format=json`
6. 前端增加下载按钮、格式选择和导出失败提示。

#### 验收标准

- 正文中的引用编号与引用列表一致；
- 无引用、无答案和部分失败报告可以导出；
- 中文、公式、代码块和表格不损坏；
- 不泄露 Provider key、内部配置和无关用户数据；
- 同一 Run 重复导出结果稳定；
- API、文件内容和前端下载路径均有测试。

### A2 数据生命周期管理

#### 首批功能

- 对话归档；
- 对话重命名；
- Run 归档；
- 文档归档；
- 软删除；
- 恢复；
- 列表按状态筛选。

第一批不直接物理删除数据库记录。

#### 状态

```text
active
archived
deleted
```

删除对象默认不出现在普通列表，但仍可在回收站查看。Evidence、Artifact 和审计关系必须保留。

#### 实施步骤

1. 暴露现有 `conversations.archived_at`。
2. 为 Run 和 Document 增加统一生命周期字段。
3. 增加 PATCH、DELETE 和 restore API。
4. 列表接口默认过滤 `deleted`。
5. React 列表增加归档、恢复和重命名操作。
6. 禁止删除仍被报告引用的 Evidence。

#### 验收标准

- 归档对象不出现在默认列表；
- 恢复后原 ID、引用和 Run 关系不变；
- 删除对话不会误删 Evidence 和 Artifact；
- 重复删除和恢复是幂等操作；
- 页面刷新后状态保持一致。

### A3 长任务反馈与通知

#### 统一状态

```text
queued
planning
retrieving
synthesizing
writing
completed
failed
cancelled
```

每个阶段至少提供：

- 当前阶段；
- 已完成步骤；
- 最近事件；
- 已消耗预算；
- 最后更新时间；
- 是否仍在运行。

#### 实施步骤

1. 统一 Run progress event schema。
2. SSE 断线后支持事件游标补发。
3. 页面刷新后恢复任务状态。
4. 增加浏览器 Notification。
5. 增加页面内完成和失败提示。
6. 任务结束后自动定位到报告或错误详情。

#### 验收标准

- 页面刷新不丢任务状态；
- SSE 重连不会重复渲染关键事件；
- 用户离开原页面后仍能看到完成通知；
- 失败任务可以直接进入错误和恢复入口；
- 至少通过一次真实深度研究 Run 验证。

### A4 React 前端回归

使用已安装的 Microsoft Edge 覆盖：

- Overview；
- Chat；
- Deep Research；
- Library；
- Note Studio；
- Settings；
- 导出；
- 归档/恢复；
- 长任务刷新恢复。

必须覆盖：

- 桌面宽屏；
- 窄桌面；
- 移动宽度；
- 空数据；
- 无答案；
- 失败 Run；
- 长标题；
- 中文、公式、代码和表格；
- SSE 重连；
- 多模态默认路径。

验收标准：

- React 版冒烟脚本可重复运行；
- 无控制台错误；
- 关键按钮可操作；
- 无明显遮挡、溢出和不可恢复加载；
- 真实服务和浏览器均完成验证。

### A5 设置生效反馈与 NotePatch

设置页统一显示：

```text
已保存
立即生效
重启后生效
当前生效值
```

Provider、模型和多模态开关至少显示保存值、当前进程值和是否需要重启。

NotePatch 409 处理：

1. 自动拉取最新版本；
2. 显示冲突位置；
3. 尝试重新应用；
4. 无法自动合并时再要求人工处理。

## 4. P6-B：Agent 能力增强

### B1 语义记忆召回

#### 目标

将当前按更新时间查询升级为：

```text
结构化过滤
→ 向量候选召回
→ recency/usefulness 重排
→ 角色和层级过滤
→ L0/L1 注入
```

#### 召回对象

- User preference；
- Project context；
- Session context；
- Procedure/experience；
- Conflict candidates。

#### 明确不做

- 不做自动无限学习；
- 不自动把所有 Run 转成长期记忆；
- 不取消 HITL；
- 不突破 L0/L1 既定注入上限；
- 不把记忆语义规则复制到多个 Agent。

#### 实施步骤

1. 明确 MemoryRecord 的文本化表示。
2. 为已批准记忆建立独立向量索引。
3. 保留 SQLite 作为权威元数据源。
4. 实现混合召回。
5. 增加 scope、category、status 过滤。
6. 增加 recency/usefulness 重排。
7. 返回召回原因。
8. 在 Memory Studio 展示“为什么召回”。

#### 验收集

- 偏好召回；
- 项目背景召回；
- 同义表达召回；
- 冲突记忆；
- 无相关记忆；
- 过期记忆；
- 多项目串扰。

#### 验收标准

- 相关记忆优先于单纯最新记忆；
- 不发生跨项目记忆泄漏；
- 无答案时不强行注入；
- 注入总量不超过既定上限；
- 召回记录包含 memory ID、scope、score 和 reason；
- 召回失败时退回确定性路径。

### B2 受限计算工具

#### 首批支持

- Python 脚本；
- CSV/JSON/文本分析；
- 基本统计；
- 简单图表生成；
- 结果文件保存。

#### 沙箱边界

- 独立临时目录；
- 只读输入挂载；
- 输出目录白名单；
- 最大执行时间；
- 最大内存；
- 最大输出大小；
- 禁止网络；
- 禁止任意系统命令；
- 任务结束自动清理临时文件。

#### Tool Contract

```json
{
  "script": "...",
  "input_artifacts": [],
  "output_paths": [],
  "timeout_seconds": 60
}
```

输出至少包含：

```json
{
  "status": "succeeded",
  "stdout_artifact_id": "...",
  "output_artifact_ids": [],
  "duration_ms": 0,
  "resource_usage": {}
}
```

#### 验收标准

- 正常计算可以生成 Artifact；
- 超时会终止；
- 非法路径被拒绝；
- 网络访问被拒绝；
- 大输出被限制；
- 工具错误不会导致 API 进程退出；
- Run 中能看到工具调用和产物关系。

### B3 工具权限分级

定义三类工具：

```text
read-only
compute
external-write
```

默认策略：

- `read-only`：可自动调用；
- `compute`：满足资源限制后自动调用；
- `external-write`：必须 HITL 核准。

每个 Run 增加允许工具列表、禁止工具列表、资源限制、审批记录和工具调用结果。

### B4 预算硬限制

第一批控制：

- token；
- tool calls；
- wall-clock time。

每次 Provider 或 Tool 调用前：

1. 预留预算；
2. 执行调用；
3. 记录实际消耗；
4. 释放未使用预留；
5. 超限后停止后续调用。

验收标准：

- 预算不足时不发起外部调用；
- 工具超限后不能通过 fallback 绕过；
- 失败结果记录 `budget_exceeded`；
- Run 状态明确为 stopped 或 failed；
- 页面展示 limit、reserved、actual 和 remaining。

货币预算待 Provider 价格模型稳定后再接入。

## 5. P6-C：执行可靠性升级

### C1 API 与 Worker 进程分离

第一步不引入 Temporal，先拆分为：

```text
API process
Worker process
Scheduler/lease
SQLite persistence
Event outbox
```

原则：

- API 负责提交、查询、取消和事件读取；
- Worker 负责执行；
- SQLite tasks/leases 作为过渡队列；
- 关键事件写入 outbox；
- 事件允许补发和重放。

验收标准：

- Worker 重启不影响 API；
- API 重启不丢待执行任务；
- Worker 崩溃后 lease 能过期；
- 任务可以由另一个 Worker 接管；
- 事件可从数据库补发；
- 已完成步骤不会重复执行。

### C2 Step 级 checkpoint 与恢复

第一批只覆盖深度研究主链路：

```text
plan
retrieve
claim
verify
synthesize
write
deliver
```

每一步保存输入摘要、输出 Artifact、状态、attempt、错误、起止时间和可恢复条件。

恢复规则：

- 可重试错误：自动重试；
- 不确定结果：标记 `unknown_outcome`；
- 外部副作用工具：禁止自动重试；
- 已有输出 Artifact 的步骤优先复用；
- 不从头重跑整个 Run。

验收标准：

- 在 retrieve 或 write 阶段终止 Worker；
- 重启后从最近 checkpoint 继续；
- 不重复生成不可区分的报告；
- 原始失败记录保留；
- 恢复后的 Run 可以追溯每一步。

### C3 MCP 健康与故障处理

补充：

- 启动健康检查；
- 调用超时；
- 子进程退出检测；
- 有限重启；
- 失败熔断；
- 当前状态展示。

该项依赖 C1 的 Worker 生命周期稳定后实施。

## 6. P6-D：暂缓或单独立项

除非近期明确公网部署，否则不纳入本轮主体：

- 鉴权与多租户；
- 备份、PITR 和恢复演练；
- OTel、指标和告警；
- 并发压测和 soak；
- 灰度发布和运行时回滚；
- ToS、频控和合规治理；
- User/Organization 多租户模型；
- Skill 分发市场；
- 复杂模型路由；
- PDF/Word 高保真排版导出；
- 冻结实验哈希功能必要性评估。

如果近期确定公网部署，应将鉴权、备份、可观测性提前为独立上线阻塞项，而不是零散混入普通 P6。

## 7. 推荐验收顺序

```text
Gate 1  A1 Markdown/BibTeX/JSON 导出
Gate 2  A2 归档、恢复、重命名、软删除
Gate 3  A3 长任务进度、刷新恢复、通知
Gate 4  A4 React 浏览器回归
Gate 5  B1 语义记忆召回
Gate 6  B2/B3 计算工具与权限
Gate 7  B4 token/tool/time 硬限制
Gate 8  C1 API/Worker 分离
Gate 9  C2 深度研究 step checkpoint 恢复
```

每个 Gate 必须记录：

- 修改范围；
- 测试命令和实际结果；
- 浏览器或真实 Run 证据；
- 失败案例；
- 未覆盖边界；
- 是否允许进入下一 Gate。

## 8. 最终取舍

P6 不追求一次性补齐所有架构短板。优先完成：

```text
A1～A5  用户可用性闭环
B1～B4  Agent 核心能力
C1～C2  执行可靠性
```

核心判断是：先让研究结果拿得出来、任务看得见、数据管得住、记忆用得上，再进行执行底座和市场化基础设施升级。
