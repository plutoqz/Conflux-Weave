# Conflux-Weave v0.3 用户全流程体验与能力闭环优化方案

- 编制日期：2026-09-16
- 文档状态：`proposed`，待确认实施范围
- 诊断基线：`main@5fcd8d9`
- 适用对象：默认 React 工作台、配套 API 与用户实际触达的执行链
- 本次交付：形成优化方案，不修改业务代码，不启动付费实验
- 核心目标：从“各模块能够运行”推进到“用户能够可信、连续、可恢复地完成研究任务”

> 本文是基于当前代码诊断形成的实施提案，不是修复完成记录，也不授权一次性实施全部阶段。所有验收项初始状态均为待执行。

## 1. 判断与方案选择

### 1.1 当前判断

项目已具备资料解析、混合检索、研究运行、笔记版本、记忆、项目分析、Skill/MCP 等底层能力。主要短板不是页面或模块数量不足，而是：

1. **能力表达不准确。**部分入口名称、成功提示、统计信息和生成结果超过实际执行范围。
2. **用户操作不连续。**页面各自维护状态，搜索、切页、刷新、重新打开、追问和恢复缺少统一承接。
3. **验收单位偏向组件。**后端机制测试、旧版页面检查和构建检查，不能覆盖新版前端的完整操作链。

因此，优先解决可信性、契约与连续使用，再扩展研究专题、阅读工作区和真实技能执行。不能用视觉重做、更多 Prompt 或更多 Agent 替代这些修复。

### 1.2 备选路线

| 路线 | 收益 | 局限与成本 | 决策 |
|---|---|---|---|
| A：优先改版页面与布局 | 能快速改善信息密度和观感 | 无法解决错误路由、假成功、版本回退和接口不匹配 | 不作为主线；随核心流程同步优化 |
| B：先修可信性和合同，再打通高频闭环 | 复用现有能力，直接减少用户失败和重复操作；便于逐关验收 | 需要同时检查前后端边界，不能只修改展示层 | **推荐主线** |
| C：先建设新研究空间和统一 Agent 平台 | 长期组织能力更强 | 会在已有断点上增加新状态、迁移和调用复杂度 | 延后至核心闭环通过之后 |

## 4. 目标、非目标与成功标准

### 4.1 高频用户旅程

**旅程 A：围绕一组文献形成研究成果**

```text
确认模型与语料能力
-> 导入或发现三篇文献
-> 确认全文与索引状态
-> 限定这三篇文献提问
-> 从回答核查证据和原文
-> 生成并修订笔记
-> 关闭、刷新后继续同一工作
-> 生成研究报告
-> 追问、导出、再次搜索定位
```

**旅程 B：结合项目代码理解并验证改动**

```text
选择项目
-> 选择文件或代码片段提问
-> 保存对话和出处
-> 明确补丁目标与范围
-> 审查差异并批准应用
-> 执行授权的验证
-> 查看结果，必要时恢复
```

旅程 A 是前四个 Gate 的主线。旅程 B 的完整闭环在 G4 推进，不应阻塞主线先交付。

### 4.2 必须达到的用户结果

1. 用户不需要手工复制 document、note、conversation、run 等内部 ID 才能完成常见动作。
2. 页面所说的执行模式、来源范围、就绪状态和完成状态与后台事实一致。
3. 刷新、切页、关闭窗口后能恢复任务、笔记版本和对象位置，不意外触发重新付费执行。
4. 失败保留输入与已有成果，给出可执行恢复动作，而不伪装成空库、无结果或成功。
5. 引用能回到具体证据和来源位置；不把有引用格式等同于事实核验通过。
6. 完成状态由“用户目标是否完成”而非“接口返回 200”决定。

### 4.3 本方案第一轮不做

- 不重写整个前端，不替换 FastAPI、SQLite、Artifact Store 或 LanceDB。
- 不增加通用 Agent 框架、自动规划平台或新的记忆体系。
- 不把多人协作、公网部署、多租户和生产级平台治理混入个人工作台体验整改。
- 不重新宣称既有模块不存在；能够复用的导出、版本、恢复、引用和生命周期能力先接通。
- 不修改历史运行、历史笔记、失败实验和验收结果以美化当前状态。
- 不在模型价格和计费口径未确认时宣称货币硬预算已实现。

## 6. 实施路线与依赖

```text
G0 固定基线与失败回放
 -> G1 可信性和关键合同修复
 -> G2 导航、会话、任务和笔记连续使用
 -> G3 核心文献研究闭环
 -> G4 项目与真实技能闭环
 -> G5 研究专题最小切片
```

- 每个 Gate 通过后单独提交、记录证据和剩余限制，不以其他 Gate 的进展抵消当前失败。
- G1 中安全净化和可信性阻断可在范围不冲突时并行；合同字段与路由仍需统一评审。
- G4/G5 是后续范围，不因前序实施授权而自动启动。
- 每批前先检查工作树、当前服务版本和计划差异；不重复完整方向讨论。

### G0：固定基线与失败回放

**范围**

1. 将 U01-U13、U20 的确定性问题转为可重复离线测试，增加“从前端实际请求形态出发”的合同检查。
2. 使用隔离 SQLite、Artifact Store 和本地测试资料，不触碰日常资料库。
3. 记录源码版本、前端 bundle、API/Worker 来源、功能配置及测试命令；敏感值只记录是否配置。
4. 为新版 React 增加组件交互和浏览器端到端测试入口。根据现有工具选择最小测试组合，不建设自制浏览器框架。

**输入数据**

- 三篇可合法使用、含清楚标题/章节/引用位置的测试文档。
- 一篇明确否定优越性的英文文档，用于验证不实降级输出。
- 一个空库，一个包含全文不可用/解析失败/索引失败条目的资料库。
- 两个会话、两个项目、多个 Run 和同一笔记 v1/v2，用于定位与隔离测试。
- Provider 不可用、返回非法结构、检索无答案等固定响应；离线测试默认禁止外部网络。

**验收**

- [ ] 已确认缺陷有独立失败回放，失败原因与诊断一致。
- [ ] 测试数据与日常数据路径严格隔离。
- [ ] 新版和旧版覆盖明确区分，构建通过不再作为交互通过的替代。
- [ ] 形成“预期行为/实际行为/证据位置/下一修复点”的基线记录。

**下一验收点：G1。**

### G1：可信性与关键合同

**G1-A：结果真实性**

- 文档分析无法可靠完成时，返回明确失败或来源摘录，不生成比较优势、显著性、实验结果等无依据结论。
- 用户笔记修订失败时保留原版本和指令，不用模板补写来制造成功。
- Skill 无执行条件时应禁用、失败或显式进入隔离演示模式；演示不得进入普通成功统计和知识沉淀。
- 分开显示实际 usage、估算 usage 和未知 usage；无真实调用不能作为实际 Token 消耗记账。
- 文献统计从服务端事实计算；零、未知、加载失败和未就绪分别处理。

**G1-B：合同与入口语义**

| 用户操作 | 目标语义 |
|---|---|
| 论文发现 | 查找候选文献，不暗示已完成全文综合研究 |
| 单 Agent 文献研究 | 调用已有 `verified_paper_research` |
| 多 Agent 文献研究 | 调用已有 `managed_verified_research`，不宣称质量必然更好 |
| 网络与本地深度研究 | 调用已有 `deep_research`；引擎不可用时明确告知 |
| 直接回答 | 明确是否使用外部搜索，不冒充本地证据核验 |
| 指定资料问答 | 按明确资料范围回答；G3 前不得伪装为已支持 |

- 修复 `query/question`、`state/status`、Skill 分类及记忆候选字段。
- 恢复动作按已有 `/resume` 与决策合同实现，不新增语义重复的接口。
- 控件必须改变实际行为；尚不支持的组合禁用或明确限制。当前仅调整回答风格的选项，不称作“闭环交叉反思”。
- 关键 API 优先使用后端 schema 约束前端类型，并以实际请求/响应回归兜底，不依赖 `any` 消除类型报错。
- 打开已有笔记先获取最新修订，不再隐式重新分析；重新分析是单独确认的新操作，不覆盖旧成果。

**G1-C：安全渲染**

- 为外部文献、项目 Markdown、模型结果和研究报告统一应用 HTML 净化与 URL 协议限制。
- 复用经过验证的净化实现，不自行用正则模拟 HTML 安全处理。
- 保留合法数学公式、表格、代码块和引用跳转，并分别验证外链、图片与事件属性处理。

**验收**

- [ ] U01-U08 的对应阻断项及 U20 分类问题回放通过。
- [ ] Provider 失败时不生成未经支持的研究结论，不出现普通成功状态。
- [ ] 空库计数为 0，未知索引状态不显示就绪。
- [ ] 追问、恢复和各研究入口发送正确合同；费用可能重复的重试需要显式决策。
- [ ] 不依赖刷新即可使用新消息导出身份和真实状态。
- [ ] 恶意内容不能通过净化链进入可执行 HTML，正常富文本无明显退化。
- [ ] 源码、构建产物、测试使用同一版本。

**退出条件：任何假成功或确定性主入口失败仍存在，不进入 G2。**

### G2：导航、会话与长任务连续性

**导航与对象定位**

- 统一处理分区、conversation、message、run、document、note revision、evidence、project 与 file 定位。
- 用户显式 URL 定位优先于上次访问状态；只有没有显式定位时才恢复最近对象。
- 导航解析不能再次写入裸分区并抹去对象参数；支持前进、后退、刷新及失效链接提示。
- 搜索结果使用结构化 locator 精确定位；不通过标题猜测目标，不把笔记命中转成重新分析。
- 快速切换对象时取消或忽略过期请求，避免旧响应覆盖当前页面。

**任务状态**

- 以现有持久化 Run 为权威，统一管理 SSE 订阅、终态查询、断线重连和刷新恢复。
- 任务中心展示真实运行和恢复状态；未进入 durable Run 的操作明确标识其恢复边界。
- 区分取消请求已接受、已取消、等待用户决策、失败、部分完成和完整完成。
- 重新运行创建新 Run 后跳转新任务，并保留父子来源；终态操作按任务种类限制。
- 通知不依赖某个对话气泡持续挂载，不强制要求用户授予系统通知权限。

**会话、笔记与记忆**

- 草稿按对象隔离保存；普通生成提供流式反馈和停止请求。停止前端等待不能谎称远端调用已中止或不再计费。
- 保留用户失败输入和状态，重试不重复追加错误消息，也不把迟到回复附到其他会话。
- 笔记冲突获取最新 `note_id + version`，保留用户指令和引用选区；内容基线改变时先展示差异再决定重应用。
- 记忆候选支持批准、拒绝、冲突提示和作用域确认。未经批准不进入长期记忆。
- 记忆入口展示 statement 和出处，避免用自动抽取置信度代替事实证明。

**验收**

- [ ] 正在运行、失败待处理、已完成任务均能在刷新后恢复准确状态。
- [ ] 同一对象可经搜索、历史列表、URL 和任务中心进入，并定位一致。
- [ ] v2 笔记重新打开仍为 v2；历史 v1 只读查看不会被当作最新版本。
- [ ] 记忆批准/拒绝状态在重开页面后保持，与召回行为一致。
- [ ] 草稿和迟到响应不会跨会话、跨项目或跨文档串联。
- [ ] 桌面和窄屏浏览器完成主要操作，无不可达控件或正文被侧栏挤出可用区域。

**下一验收点：G3 的文献研究黄金路径。**

### G3：资料、证据与研究成果闭环

**资料准备**

- 接通已有本地上传、解析、索引、重试与生命周期接口。
- 文档条目同时展示生命周期和处理状态，不把“活跃”当成“知识库可用”。
- 批量操作保留单条结果：元数据保存、全文获得、解析完成、索引就绪分别计数。
- 支持本地资料搜索、过滤、分页或渐进加载，避免所有长列表一次渲染。
- 论文发现展示来源成功/失败与返回边界；不能把来源失败呈现为确定不存在相关论文。
- 配置中心按任务展示 Chat、Embedding、Reranker、图像索引、研究引擎的必要条件及生效状态。

**限定范围与引用**

- 引入最小的显式资料范围：全库、指定 document 集合，以及来源快照/版本记录；保持旧请求缺省行为兼容。
- 范围约束必须下沉到检索执行，不只写进 Prompt。
- 严格本地模式禁用外部来源补充；混合模式明确外部来源和本地核验的不同证据状态。
- 回答保留 citation、verification 和使用来源；对无答案、部分支持、来源缺失给出可检查说明。
- 证据列表显示真实总数和分页，不把截断结果标成全部。

**阅读与笔记**

- 先区分“摘要级阅读”“针对章节精读”“覆盖全文的研读”，显示实际处理章节及未覆盖部分。
- 使用分章节处理或按问题定位的方式构造上下文，记录截断和覆盖，不通过无限增大 Prompt 掩盖长文问题。
- 生成小节的 source_segments 指向真正支持内容的来源；无法定位则明确未锚定。
- 复用现有页码分组和选区引用，补充原版 PDF 联动与阅读位置恢复。
- 笔记导出、保存为研究成果、报告追问保留原始引用、范围和版本。
- 追问中的“第三节”“上述方案”需要明确绑定父报告或选区；继承父上下文不等于免除新结论的核验。

**验收**

- [ ] 旅程 A 可从空库走通，不需要人工复制内部 ID。
- [ ] 指定三篇文献的问题不会引用第四篇或被排除版本。
- [ ] 无答案案例不会通过额外生成掩盖资料不足。
- [ ] 人工抽查每个主要结论可回到支持它的段落、页码或图表。
- [ ] 关闭、刷新、再搜索后，笔记版本、报告范围、引用和导出一致。
- [ ] 成功、空结果、部分失败和恢复四类路径均完成浏览器检查。

**退出条件：仅离线通过但真实 Provider 验证未执行时，标记 `implemented_offline`，不得标为真实能力验收通过。**

### G4：项目与真实 Skill 闭环

本阶段开始前独立确认范围，不自动扩展为完整编码平台。

**项目工作流**

- 持久化项目问答、选中文件和引用；提问请求携带项目、文件、选区与源码版本。
- 不再仅根据“架构”等关键词把具体问题替换成固定介绍；明确区分导航命令、分析问题和修改请求。
- 未能确定补丁目标时要求选择目标，禁止默默回退到默认文件。
- 保留已有路径保护、哈希冲突保护、差异预览和人工批准。
- 补充输出截断检查、适用文件类型校验和验证计划；“写入成功”与“测试通过”分开。
- 执行验证只运行用户批准范围内的命令；恢复只作用于本次改动，不覆盖用户并发修改。

**Skill 工作流**

- 先选一个文献对比 Skill 和一个代码审计 Skill，证明从对象选择到工具调用的真实闭环。
- Skill 输入从资料库/项目选择，不要求用户手填 ID。
- `required_tools` 进入真实可执行检查和调用链；工具权限、范围和结果必须可追溯。
- 复用已有 Harness、Run 和 Artifact，不另建一套技能任务数据库。
- 落实输入输出、预算、部分失败、取消和恢复语义；不宣称未知结果的外部调用可自动安全重放。
- 结果回到所属会话或研究对象，并支持再次打开和导出。

**验收**

- [ ] 项目切换或刷新不丢会话，提案目标与选中文件一致。
- [ ] 文件被外部修改后拒绝直接覆盖；应用后有独立验证状态。
- [ ] 两个 Skill 均有真实输入对象、真实工具 trace 与结果 artifact。
- [ ] 目标不存在、工具缺失、预算不足、Provider 失败均如实失败或部分完成。
- [ ] 不把工具接通等同于模型分析质量优秀；后者单独人工评审。

### G5：研究专题最小切片

**进入条件：G3 已通过，已有真实使用案例表明跨对象整理仍是主要成本。**

- 先增加“专题与已有对象的关系”，不复制文档全文、笔记历史或运行状态。
- 最小功能为专题名称、研究问题、关联资料/笔记/报告/代码项目、最近工作位置。
- 研究专题与代码项目语义分开，具体表结构、迁移与 API 在阶段开始时冻结。
- 不先建设自动分类、自动 KG、生成人格记忆或复杂知识组织算法。
- 旧数据默认保留未归属状态，不自动迁入臆造主题。
- 标签、收藏、跨文献对比矩阵和版本对照仅在明确使用案例下逐项加入。

**验收**

- [ ] 同一专题中可完成检索、笔记、研究、代码引用及成果回看。
- [ ] 删除专题关系不会删除底层资料或历史成果。
- [ ] 专题范围和代码项目范围不会混淆，来源和作用域可以解释。

### 8.2 指标与停止规则

- 固定阻断用例通过率要求 100%；不能用其他成功案例抵消确定性失败。
- 未授权来源进入限定资料结果、旧版本被静默覆盖、假成功、无依据研究结论均为阻断项。
- 记录用户额外操作次数、刷新后的恢复成功率、错误后的输入保留率。
- 延迟分别记录接口、首个反馈、完整结果和渲染耗时；先冻结基线，再制定各模式合理门槛，不凭空统一承诺响应秒数。
- 浏览器检查桌面与窄屏，主要功能可键盘操作，错误不只写入控制台。
- 真实模型测试前记录问题集、模型、Provider、参数、范围、预算上限、停止条件和人工核查表。
- 离线阶段默认零付费调用；真实验证范围与预算另行确认，不因本方案存在而自动授权。
- 保留失败与未知结果，不自动重试付费未知结果，不更换问题或指标来制造通过。

## 9. 发布、回退与恢复

- 修改前记录当前分支、工作树、服务进程、API/Worker 源码版本和真实数据位置。
- 前后端合同变化协调发布；保留旧持久化数据读取能力，不依赖清空数据库解决兼容问题。
- 有迁移时先在数据副本验证；备份能力先验证可恢复，再用于真实数据变更。
- 新研究范围和专题功能支持灰度或可逆开关；不为本次计划新建复杂配置平台。
- 安全和可信性修复不以“回退到已知危险路径”作为正常恢复方案；必要时暂时禁用能力。
- 笔记和报告用新版本保存，不覆盖历史产物；重新分析记录原始来源与父版本关系。
- 代码修改的恢复先比较当前哈希，仅恢复本次批准改动，不能覆盖后续用户编辑。
- 服务重启后检查 API/Worker 和 bundle 来源，再验证实际交付页面；仅测试源码不算发布通过。

## 10. 计划外问题与停止条件

出现以下情况时暂停扩展，保留证据并报告：

1. 需要删除或不可逆迁移日常数据，且没有验证过的恢复路径。
2. 需要改变任务成功标准、默认外部来源权限、费用预算或研究主张。
3. 修复必须重写执行引擎、引入大型框架或扩展为多人平台。
4. 真实调用结果未知，继续可能重复付费或产生重复副作用。
5. 确认的问题无法在当前 Gate 范围内修复，需要新的 schema 或架构决策。
6. 浏览器或 Provider 条件不具备，只能完成离线验证；应保留未验证状态，不用其他测试替代签收。
