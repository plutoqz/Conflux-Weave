> 设计依据：`docs/design/current/Conflux-Weave设计文档v0.2.md`

## 1. 目标、主张与成功标准

W1 只建立一条本人可用的最小链路：

```text
研究问题 -> 一个已登记来源 -> 检索或读取 -> Evidence -> 声明级引用回答
```

阶段主张只有一个：在明确授权的本地文档或官方仓库搜索输入上，用户可以不查看
源码，通过本地 CLI 获得中文、可打开引用、保留失败边界的研究结果。W1 不主张
完成通用 Agent、完整 RAG、论文雷达、多源综述或生产 Runtime。

里程碑必须同时满足：

1. 本地文档和官方仓库搜索两条入口均形成 SourceSnapshot、Evidence、Claim、
   Citation 与 Markdown 报告。
2. 缺失输入、无答案和来源失败不会生成伪引用，并给出可行动恢复路径。
3. Phoenix、Ragas、DeepEval 和 LangGraph 未安装时核心链路仍可运行。
4. 两次经授权的真实端到端查询保留 Provider、模型、Prompt、预算、原始响应、
   失败记录和产物 hash。
5. 至少一份结果被用户实际用于阅读笔记、综述或项目判断。

## 2. 方案比较与决策

| 方案 | 收益 | 局限与成本 | 决策 |
|---|---|---|---|
| A：仅本地文档 | 最快形成引用闭环；无网络依赖 | 无法验证系统自主定位官方项目和仓库 | 不选 |
| B：本地文档 + 仓库搜索，单 Fixed Workflow | 覆盖两类核心输入；仍能限制为单进程、单一登记来源 | 不能完成多源综述或四对象完整比较 | **选择** |
| C：多源、多 Agent 工作台 | 功能面最完整 | 在首个真实任务前引入规划、并发、恢复和评测平台 | W1 拒绝 |

W1 用户入口固定为本地 CLI，Runtime 固定为单进程同步执行。Web UI、FastAPI、
Worker、队列、SSE、SQLite 和跨进程恢复延后；CLI 必须支持提交、查看进度、打开
最终报告和引用定位，不能退化为只能从 Python 调用的库。

## 3. 真实输入与验证集

### 3.1 两个 live 输入

`W1-LIVE-01` 映射 `CW-PR-006`：用户明确提供并授权处理的一篇真实综述 PDF 或
UTF-8 Markdown，默认输出中文详细紧凑阅读笔记。关键结论必须定位到页码或标题/
行范围；没有获准的第二来源时，将扩展点写成待补证问题，不把模型背景知识写成
外部事实。用户未提供文档时，W1.5 保持阻塞，不用测试 fixture 冒充真实输入。

`W1-LIVE-02` 是 `CW-PR-002` 的身份解析切片：系统定位 pi coding agent 的官方
仓库，说明规范名称、维护者、官方 URL 和可公开证实的实现入口。结果作为后续四
对象比较的身份基线；它不能被标记为完整通过 `CW-PR-002`。

### 3.2 确定性验证

| 验证 ID | 映射案例 | 风险与预期 |
|---|---|---|
| `W1-LOCAL-SUCCESS` | `CW-PR-006` | 本地文档形成可定位引用；live 仍需真实授权文档 |
| `W1-REPOSITORY-IDENTITY` | `CW-PR-002` | 自主定位和消歧官方仓库；只验身份切片 |
| `W1-MISSING-DOCUMENT` | `CW-PR-011` | `waiting_for_user`，不生成摘要和引用 |
| `W1-NO-ANSWER` | `CW-PR-010` | 不满足硬约束时 `no_answer`，不静默放宽 |
| `W1-SOURCE-FAILURE` | `CW-PR-012` | 结构化失败；有证据才 partial，无证据不伪交付 |

确定性 fixture 只证明机制和合同，不代替 live 输入。W1 不迁移旧三语 30 题集、
P2 radar、Chroma 或历史 Runs；这些资产等待实际 W2 消费者。

## 4. 数据、引用与文档边界

| 对象 | 存放位置 | W1 规则 |
|---|---|---|
| 原始 Source/响应 | `var/artifacts/sha256/` | 内容寻址，不原位覆盖；记录身份、时间、媒体类型、hash 和限制 |
| 导入暂存与 Manifest | `var/imports/` | 用户文档不进入 Git；记录授权和解析状态 |
| 对外交付 | `var/exports/` | Markdown 报告及引用入口，不作为 Runtime 状态源 |
| 验证原始结果 | `var/evaluations/` | 保存成功、失败、预算和原始响应；不回写业务状态 |

PDF 引用使用页码和文本片段 hash；Markdown 使用标题路径和行范围；GitHub 搜索
结果使用规范 URL、仓库身份、查询时间和响应片段 hash。搜索候选响应是发现过程的
Artifact；只有被选中的官方仓库身份进入 Evidence。W1 不实现向量索引，单一登记
来源内先使用确定性分段与有界上下文选择。State/Event、Artifact、Evidence 和
Trace 不得互相代替。

## 5. Provider、网络与隐私授权

本次 scope freeze 只授权计划与合同文件，不授权 W1 编码、网络请求或模型调用。

- 本地 deterministic fixture：收到下一次实施指令后可使用。
- tracked 仓库文档：只允许离线 parser 测试，不作为真实能力证据。
- 用户私有文档：逐文件明确授权；只进入 `var/`，不进入 Git、Trace 或测试 fixture。
- GitHub 公共搜索：live run 前单独确认网络执行；保存查询、时间和原始响应 hash。
- Model Provider：live run 前冻结 Provider、模型、Prompt、参数、预算和 Secret 来源。
- Codex 当前会话不能被假设为可供产品 Runtime 调用的 Model API。
- 付费服务、付费评测和无上限重试未授权。

若 W1.5 前仍缺少真实综述、Provider 配置或网络授权，对应 live 验收保持
`blocked_external`，不得用 replay、HTTP 成功或 fixture 冒充 `validated_live`。

## 6. 工作包与验收点

| 验收点 | 状态 | 实施范围 | 最小验收 |
|---|---|---|---|

| W1.1 CLI + Fixed Workflow 骨架 | `validated_offline` | 单进程入口、Task/Run/Step、deterministic adapters | 53 tests；两种 CLI 入口运行；内容寻址 Artifact hash 复核通过 |
| W1.2 本地文档闭环 | `validated_offline` | PDF/Markdown import、确定性分段、SourceSnapshot、Evidence/Citation、报告 | 58 tests；Markdown 成功/缺失和 PDF 格式边界通过；报告 Artifact 可打开 |
| W1.3 仓库搜索适配器 | `pending` | GitHub 仓库搜索、身份归一化、SourceSnapshot | recorded contract test 通过；失败不伪造候选 |
| W1.4 失败与解耦 | `pending` | no-answer、partial/failure、预算、最小诊断 | 禁用可选框架仍运行；引用确定性检查通过 |
| W1.5 真实使用验收 | `pending` | 两次获授权 live run 和用户使用决策 | 满足设计的五项 W1 验收；原始证据完整 |

预计 W1.3-W1.5 剩余实施预算 14 至 26 个有效工时；若实际消费者不需要某项，不为填满框架而
实现。每个验收点独立提交、验证和更新状态，同一时刻只推进一个。

## 7. 实施顺序与退出条件

W1.1 先使用 deterministic adapters 建立 CLI 和 Fixed Workflow，不接真实网络或
Provider。W1.2 让本地文档闭环成为第一个完整消费者，再据此稳定最小 Ports。
W1.3 只增加一个 GitHub 仓库搜索 Adapter。W1.4 集中验证失败语义和框架解耦。
W1.5 最后在配置、预算和授权齐备后运行真实任务。

立即停止并报告：

- 首个真实任务必须依赖多源综合、完整四对象比较、论文雷达或多 Agent。
- SQLite、服务端队列、Web UI、LangGraph 或评测框架成为黄金路径前置。
- 需要复制旧 Conflux 模块、Runtime DB、Chroma 或历史结果。
- 连续两次修改只增加 Prompt、重试或案例特判，未解决结构性失败。
- live 验证缺少用户文档授权、Provider/模型/预算或网络授权。

## 8. 当前检查点

W1.0-W1.2 已达到 `validated_offline`。W1.2 新增：

- `conflux-weave validate-workflow` 和 `python -m conflux_weave` 两种本地入口。
- `accepted -> queued -> running -> succeeded/failed` Run 轨迹，以及对应 Step 轨迹。
- `LocalArtifactStore` 的 SHA-256 内容寻址、幂等写入和损坏检测。
- deterministic adapter 成功/失败路径；失败不重试、不 fallback，并保存诊断 Artifact。
- 明确的 `validation_only=true`、`capability_claim=none` 和 Evidence boundary；不创建
  DeliveryRecord，不把运行骨架成功解释为研究任务完成。
- PDF 与 UTF-8 Markdown 的本地导入；Markdown 分段保留标题和行范围，PDF 分段保留页码。
- SourceSnapshot、原始 Source Artifact、分段 Artifact 和 Markdown 报告 Artifact 的
  内容寻址闭环；报告引用反向指向 Evidence 和稳定 locator。
- 缺失文档返回 `waiting_for_user`，不生成摘要、Evidence 或伪引用；不支持的格式失败关闭。

实际离线证据：Python 3.12.9，58 tests passed，compileall、lock check 和 wheel 构建
通过。控制台脚本产物为
`artifact-sha256-1e491b32491f7b89ee12912543a748e98caf6680f3e5fef384e99083cffd1275`，
文件 hash 与地址一致，保存在忽略 Git 的 `var/artifacts/sha256/`。本轮没有网络、
Provider、真实文档或旧 Conflux 数据调用，因此仍不具备 Research Query 能力。

下一单一验收点是 **W1.3：实现官方 GitHub 仓库 SearchPort Adapter，记录候选发现
Artifact、规范化仓库身份和单一登记来源边界；通过离线响应合同、消歧和网络失败测试。**
