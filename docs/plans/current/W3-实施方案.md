## 1. 阶段目标、主张与成功标准

W3 围绕 W2 已经形成可用交付的研究查询，补齐单机长时运行所需的持久状态、
中断恢复、取消、预算硬停止和结构化诊断：

```text
提交 -> SQLite 队列 -> 单 Worker -> Step checkpoint
     -> Evidence/Citation 校验 -> 原子发布 -> 可解释终态
```

阶段主张是：迁移后的 `discover-papers` Fixed Workflow 可以在单机进程中断、
Worker 重启、lease 过期、超时或取消后，从 SQLite 和 Artifact 恢复，或进入明确、
可行动的终态；恢复不会静默重复结果未知的 Provider 调用，也不会把预算耗尽、
取消或缺少最终 Artifact 伪装成完整成功。

该主张只覆盖 W3 明确迁移的论文发现工作流。W1 的 `review-document` 和
`research-repository` 在 W3 仍保留现有同步入口，不声称已经具备跨进程恢复能力。
通用 Runtime、生产服务、多 Worker 和所有工作流迁移均不属于本阶段主张。

W3 完成必须同时满足：

1. SQLite 成为 Task、Run、Step、Attempt、Lease、Budget、Error、Delivery、
   Artifact 元数据及迁移工作流 Evidence 关系的权威状态源。
2. Worker 被强制终止后，已提交 Step 不重复；安全步骤可重放；未知 Provider
   副作用不自动重放。
3. 取消或预算耗尽后不再启动新的搜索、Provider 或其他外部调用。
4. 最终 Artifact、Delivery 和 Run 终态在同一发布事务中可见。
5. Trace 依赖或 Exporter 不可用时，同一研究任务仍能完成。
6. 现有 W0-W2 回归全部通过，且迁移前后的冻结 live 任务交付质量不下降。

## 3. 方案比较与决策

| 方案 | 收益 | 局限与风险 | 决策 |
|---|---|---|---|
| A：给现有单体工作流增加 Run 快照 | 改动最小 | 无 Step checkpoint；Provider 可能重复；不能满足 W3 恢复语义 | 拒绝 |
| B：单 SQLite、单 Worker、分步 Fixed Workflow | 覆盖真实副作用和恢复边界；符合首版复杂度预算 | 只迁移一个消费者，不代表所有工作流耐用 | **选择** |
| C：FastAPI、多 Worker、通用调度和全部工作流迁移 | 功能面完整 | 提前建设平台，扩大并发、部署和迁移风险 | 拒绝 |

W3 采用方案 B。SQLite 和 Worker 只服务已存在的 Research Query；不把 Runtime、
Trace 或故障注入包装成独立产品线。

## 4. 固定工作流与副作用语义

`discover-papers` 拆为以下最小恢复单元：

| Step | 行为 | 副作用分类 | 恢复规则 |
|---|---|---|---|
| `search_arxiv` | 请求 arXiv 并提交原始响应、SourceSnapshot 和 manifest | 外部只读，可重复但会消耗网络配额 | 已有完整响应 Artifact 时复用；无响应时允许新 attempt 重放 |
| `rank_candidates` | BM25 排序和选择候选 | `none` | 根据冻结输入确定性重放 |
| `synthesize_claims` | 调用 Provider 生成结构化 Claim | 付费且结果可能未知 | 有完整响应 Artifact/response ID 时复用；结果未知时暂停并要求显式恢复决定，禁止自动重放 |
| `validate_delivery` | 解析 Claim，校验 Evidence/Citation 和边界声明 | `none` | 确定性重放；失败保留响应和 Error |
| `publish_delivery` | 编译报告、manifest 和 Delivery，提交终态 | 本地幂等写 | 可重放；最终 Artifact 与 Run 终态原子可见 |

创建 Run 前执行 Accept/Freeze：规范化输入并生成幂等键，冻结 code revision、
workflow、Prompt、Provider/model、参数、预算、来源范围和数据版本。相同幂等键返回
同一个逻辑 Task；显式重新运行必须创建新 Run，并记录 predecessor。

Provider 请求若在响应 Artifact 提交前中断，Runtime 只能知道“结果未知”。除非适配器
能够用外部幂等键或响应 ID 核验，该 Step 进入 `waiting_for_user` 或结构化失败，不能
以 retryable 为由自动再次调用。

## 5. SQLite 权威状态与事务

W3 最小 schema 覆盖：

- `schema_migrations`：单向 migration、版本和 checksum。
- `tasks`、`runs`、`steps`：逻辑任务、冻结执行和恢复单元。
- `attempts`、`leases`：Worker 所有权、fencing token、心跳和过期时间。
- `run_events`：状态变化、恢复原因、原 Worker 和 attempt 关联。
- `budget_limits`、`budget_entries`：限制、预留、实际使用、释放和调整来源。
- `artifacts`、`deliveries`、`errors`：内容地址、lineage、交付和结构化失败。
- `source_snapshots`、`evidence`、`claims`、`citations`：迁移工作流最终证据关系。

原则：

1. 业务模块只依赖 Repository，不持有裸 SQLite connection。
2. 启用 foreign keys、busy timeout；单 Worker 下保持单写入通道。
3. 领取 Step 时创建新 attempt 和单调 fencing token；旧 attempt 即使恢复运行也不能
   提交状态、预算或最终 Artifact 引用。
4. Run 终态、Delivery 和最终 Artifact 元数据在一个数据库事务内提交。
5. 原始来源、Provider 请求/响应和报告正文仍保存到文件 Artifact Store；SQLite
   保存权威元数据和关系，不保存 Secret 或无界原文副本。
6. Migration 不读取旧 Conflux 数据库；W2 历史运行保持静态验收记录，不伪装成
   W3 原生 Run。

## 6. Artifact 原子提交

`LocalArtifactStore` 改为在目标目录写临时文件，flush/fsync 后用原子 rename 发布，
必要时同步父目录。恢复不接受以下状态：

- 数据库引用不存在或 hash 不一致的 Artifact。
- 最终路径存在但内容不符合内容地址。
- Run 已进入成功/部分成功终态但 Delivery Artifact 不可读。

进程可能在文件 rename 后、数据库提交前留下孤立内容地址文件。该文件不构成业务
成功；后续相同内容可以安全复用，并由恢复 attempt 正式登记。清理孤立文件不属于
在线成功路径。

## 7. Worker、Lease、取消与恢复

- 首版只有一个 Worker、并发度 1；不实现公平调度或优先级队列。
- Worker 事务领取一个可执行 Step，获得有期限 lease 和 fencing token。
- 后台 heartbeat 只能延长当前 attempt；lease 过期后由新 attempt 接管。
- 在每个外部调用前、调用后和发布前检查取消与预算状态。
- 取消是协作式的：已进入阻塞网络调用时不承诺立即中止，但调用返回后不得启动新
  Step，也不得把 Run 发布为成功。
- 超时按冻结 deadline 进入结构化终态；不通过自动扩大超时或预算补救。
- `resume` 只处理非终态 Run。终态重跑创建新 Run，历史记录不覆盖。

## 8. Budget 合同

W3 将当前 Budget 上限拆成三个对象：

1. `BudgetLimit`：墙钟 deadline、输入/输出 token、工具调用、检索轮数、并发和可选
   金额上限。
2. `BudgetReservation`：外部调用前预留的调用次数、输出 token 和其他可确定资源。
3. `BudgetUsage`：Provider/工具报告的实际使用，以及预留释放记录。

可在调用前确定的资源必须先预留；不足则不发起调用。输入 token 和金额若只能由
Provider 响应确定，响应后如超限则禁止后续调用并以预算失败或有证据的 partial
关闭，不能撤销已经发生的费用。没有冻结价格快照时只记录
`cost_enforcement=unavailable`，不得声称金额硬上限已验证。

最终综合、Citation 编译和 Artifact 发布保留独立本地预算，前序步骤不能耗尽所有
资源后仍把 Run 标记为正常完成。

## 9. 诊断与可选 Trace

结构化 `ErrorRecord` 至少保存 code、category、stage、retryable、用户说明、技术详情
Artifact、受影响 Artifact 和恢复动作。用户默认看到原因、影响和下一动作；外部异常
类型不能直接泄漏成稳定 CLI 合同。

OTel/OpenInference 只作为可选诊断适配器：

- Span 关联 `task_id/run_id/step_id/attempt_id`、workflow、Provider/model、预算和
  Artifact 引用，不记录 Secret 或完整敏感正文。
- Trace 不拥有 Run 状态，不写业务 Artifact，不参与成功判定。
- 未安装依赖、Exporter 超时或抛错时记录 telemetry drop 计数，核心任务继续。
- Phoenix 仅允许作为本地开发观察面，不进入默认依赖或验收前置。
- W3 没有 Bounded Planner，因此不接入 DeepEval。

## 10. 用户入口

W3 继续使用本地 CLI，不建设 FastAPI、SSE 或 Web UI。命令名称可在 W3.1 实现时按
现有 CLI 风格做不改变能力的调整，但必须提供以下操作：

- `submit`：提交冻结任务，返回 `task_id` 和 `run_id`。
- `worker`：启动单 Worker，处理 SQLite 队列。
- `status`：查看 Run、当前 Step、预算、Error、Delivery 和 Artifact。
- `cancel`：请求取消，并显示是否仍有 in-flight 调用。
- `resume`：对可恢复非终态 Run 创建新 attempt 或给出不能自动恢复的原因。

W5 才负责工作台 UI、SSE cursor、安装首次成功和历史 Runs 的完整产品体验。

## 12. 故障注入与确定性验收

至少冻结以下故障点：

| 故障 | 预期 |
|---|---|
| 相同幂等键串行/并发重复提交 | 一个逻辑 Task，不产生重复 Run 副作用 |
| Worker 在外部调用前被 kill | lease 过期后安全创建新 attempt |
| arXiv 响应 Artifact 提交后被 kill | 恢复复用响应，不再次搜索 |
| Provider 请求发出但响应未提交时被 kill | 结果未知；暂停或失败；零自动 Provider 重放 |
| Provider 响应 Artifact 提交后被 kill | 恢复复用响应，不产生第二次 Provider 调用 |
| 报告文件 rename 后、数据库发布前被 kill | Run 不提前成功；恢复登记并原子发布 |
| lease 过期后旧 Worker 恢复 | fencing 拒绝旧 attempt 提交 |
| queued/running 时取消 | 不启动后续外部调用，最终为 cancelled 或明确失败 |
| 预算预留不足或实际超限 | 不调用或停止后续调用；不得完整成功 |
| Trace 依赖缺失/Exporter 抛错 | 相同 deterministic Delivery 完成，Trace drop 可诊断 |
| 恢复后 Citation 编译 | 每个 Citation 仍解析到 Evidence 和 SourceSnapshot |

故障注入使用真实 SQLite、真实文件系统和真实子进程终止，但网络和 Provider 使用
fixture。它证明本地恢复机制，不证明 live Research Query。

## 13. Live 验收与非回归

W3.6 需要新的显式授权，并冻结 Provider、模型、Prompt、预算、网络、代码 revision
和精确输入。配对任务使用 W2 已接受的两个论文发现任务：

- `W2.5-LIVE-01`：上下文管理/相关性边界论文发现。
- `W2.5-LIVE-03-R3`：GIS/地理空间论文发现。

接受条件：

1. 两个 Run 均形成不弱于原结果的可用 `partial`；不强求升级为 `complete`。
2. 每个 Run 的搜索和 Provider 调用次数不高于 W2 对照，且无自动 retry/fallback。
3. 关键 Claim、Evidence、Citation 闭合率保持 100%，来源和全文限制不减弱。
4. 原始响应、预算 usage、SQLite 状态、Attempt/Lease、Trace 引用、报告和 hash 保留。
5. 用户可仅通过 CLI 状态和报告理解结果、失败和恢复动作，不依赖源码。

若授权或外部条件不具备，W3 最多标记为恢复机制 `validated_offline`；不得复用 W2
旧 live 结果冒充 W3 live 验收。

## 14. 回滚、恢复与停止条件

回滚：W3 新路径通过独立 CLI/Repository 边界接入；现有同步命令在 W3.6 前保持可用。
若持久路径导致交付回归，禁用新入口并恢复 W2 同步工作流，不覆盖 SQLite、Artifact
或失败记录。Migration 只向前；修正采用新版本，不回写已执行 migration。

立即停止并报告：

- 恢复要求第二套调度器、多 Worker 协调、远程执行或复杂分布式存储。
- 为了统一所有工作流而扩大到 `review-document`、`research-repository` 或新任务类型。
- Provider 结果未知却必须自动重试才能让测试通过。
- 预算或取消语义只能通过 Prompt、延长超时或增加 fallback 掩盖。
- Trace、Phoenix、评测或故障看板成为生产路径依赖。
- 真实任务完成率、交付可读性、Evidence/Citation 或来源边界相对 W2 下降。

## 15. W3.1 实际验收

W3.1 在 revision `7c6df6fe848df0ad0bcaf89866d68a0509f22ae8` 完成：

- migration v1 带版本和 checksum，SQLite 持久化 Task、初始 Run/Step、Delivery、
  Artifact 元数据及多 producer lineage；相同幂等键串行或并发提交只产生一个逻辑
  Task 和初始 Run，不同 payload 冲突会失败关闭。
- `succeeded`/`partial` 不能通过普通状态迁移写入；Delivery、Artifact 登记和 Run
  终态在同一 `BEGIN IMMEDIATE` 事务发布，缺失或损坏 Artifact 不会形成成功终态。
- Artifact 先写同目录临时文件并 fsync，再用原子 replace 发布；注入发布失败后无
  最终文件和临时残留。
- 聚焦测试 `12 passed`，完整回归 `140 passed`，compileall、build 和 diff check
  均通过。验收证据见 `W3.1-SQLite-Artifact验收.json`。

证据边界：只使用 deterministic fixture、临时 SQLite 和本地文件系统；网络调用和
Provider 调用均为 0。此验收不证明 `discover-papers` 已经持久执行、可跨进程恢复，
也不证明 Worker/Lease、Budget、Trace 或 live Research Query 能力。

checkpoint 可恢复、未知 Provider 结果不会重放，或 live Research Query 能力。
