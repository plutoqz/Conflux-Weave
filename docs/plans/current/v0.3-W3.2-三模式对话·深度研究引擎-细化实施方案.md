# Conflux-Weave v0.3 W3.2 三模式对话·模式 C（深度研究引擎 / GPT Researcher 证据桥）细化实施方案

三模式第三片。核心原则（用户确认）：**GPT Researcher 仅承担发现与聚合（原 ①② 层），
永远不承担引用权威与验证者**（③-⑥⑨ 层与确定性兜底不变）。

## 1. 依赖与版本

- `gpt-researcher @ git+https://github.com/assafelovic/gpt-researcher@6f99857`：
  PyPI 0.16.0 存在 `actions/query_processing.py` 缺 typing 导入的发布缺陷，锁定上游
  master 提交（实测可导入）。langchain 为其传递依赖，仅在适配模块使用，不进 domain 层。

## 2. 引擎桥（GPTResearcherBridge）

- 输入映射：我们的 ProviderConfig → GPT-R/litellm（OPENAI_API_KEY / OPENAI_BASE_URL
  环境变量执行期设置并恢复；cfg.smart_llm_model/fast_llm_model 设为我们的模型；
  retriever 默认 duckduckgo（无 key），环境存在 TAVILY_API_KEY 时可用 tavily）。
- 本地语料：执行前用现有 Hybrid 检索取 Top-8 chunk 包装为 LangChain Documents，
  `report_source="hybrid"`（web + 本地混合）。
- 进度：`on_progress` 回调原样上抛（后续可转 SSE）；token 记账经 litellm 回调
  best-effort 累计（失败不阻断）。
- 输出：sources（url/title/content）、report markdown、planned queries、costs。

## 3. 证据桥与工作流（DeepResearchWorkflow）

- 快照台账：每个 source 的正文 → 内容寻址 Artifact（sha256）→ SourceSnapshot
  （canonical_uri/acquired_at/content_hash）→ EvidenceRef（locator 记 url）。
  v1 不重爬页面：快照内容 = 聚合器交付正文（manifest 明示该边界）。
- Claim 链路：复用 VerifiedResearchWorkflow 的 draft/verify/修复轮逻辑 → Citation
  闭合 → 中文事实卡片 → Writer v2（三重质量门）→ 失败走确定性组装（禁止降级）。
- manifest：engine/model/retriever、每个 source 的 url/title/hash、usage、
  report_contract、writer_status、distill_status、限制（GPT-R 仅用于发现聚合）。

## 4. durable 与 API

- 新任务类型 `deep_research`：durable submit 冻结预算分支（23→32 调用上限、
  检索轮 4、时长 1200s）；执行器适配器按 kind 分派；批内不透明语义沿用
  （取消/未知结果保护为批级，manifest 显式声明）。
- API：`POST /api/v1/tasks/deep-research`；对话"深度研究"模式切换到该端点。
- 引擎未安装/不可导入时：任务类型不注册（提交报无运行时），服务其余功能不受影响。

## 5. 验收

- 单元：假 bridge 端到端（快照台账、claim 链路、v2 报告、manifest、no-answer）、
  执行器分派、durable 预算分支、API 端点。
- 端到端：真实引擎烟测（三题之一，web+本地混合），检查报告引用与快照台账。
- 回归：389+ 项测试全过；UX1 浏览器脚本不回归。
