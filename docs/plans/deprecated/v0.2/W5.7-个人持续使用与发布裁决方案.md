# W5.7 个人持续使用与发布裁决方案

> 状态：`已执行，发布裁决 reject`
>
> 前置：W5.6 `validated_live_bounded`
>
> 裁决：`docs/plans/current/W5.7-个人持续使用与发布裁决.json`

## 目标

验证 Workbench 是否能支持真实个人工作，而不是只完成一次演示：累计至少 5 个真实任务单元，覆盖 2 个既有任务 family，其中至少 2 次通过 Workbench 黄金路径，至少 1 份交付被用户确认用于笔记、综述、实验或项目判断。

## 执行范围

1. 冻结 5 个任务输入、任务 family、Provider、模型、预算、时间窗口和成功判定。
2. 复用当前 Fixed Workflow；不重新启用 W4 被拒绝的 Planner，不扩建第二条耐用 Workbench 垂直切片。
3. 至少 2 个任务通过 Workbench 完成提交、进度观察、交付查看、Evidence 打开和历史复用。
4. 至少覆盖一个论文发现 family 和一个既有项目证据/Q&A family；第二个 family 仅用于个人使用审计。
5. 记录每个任务的原始输入、Run ID、Provider/来源调用、预算、状态、Evidence、限制、失败和用户用途确认。
6. 最后执行发布裁决：通过、部分通过需整改，或拒绝发布。

## 验收标准

- 真实任务单元数不少于 5，且失败/重跑不重复计数。
- 至少 2 次 Workbench 黄金路径完成。
- 至少 2 个既有任务 family 有证据覆盖。
- 至少 1 份交付有用户确认用途。
- 所有交付保留 Citation/Evidence/限制边界，不能以无引用摘要计为成功。
- 未知外部结果不自动重放，失败和未满足条件保留。
- Secret、原始 Provider 敏感响应和本地隐私不进入 Git 或公开交付。

## 非目标与停止条件

- 不为达到数量增加 Prompt 特判、自动重试或放宽证据标准。
- 不新增 Agent、Memory、GraphRAG、第二服务、第二 Worker 或发布基础设施。
- 任一任务要求改变 W5 权威状态语义、预算、Evidence 或 fencing 合同时暂停并报告。
- 外部 Provider/研究来源授权、预算或用户用途确认缺失时不计入通过任务。

## 预期交付

- `docs/plans/current/W5.7-个人持续使用与发布裁决.json`
- 任务审计表、原始响应和失败证据保存在忽略的独立证据根。
- 项目状态更新为明确的 `validated`、`partial` 或 `rejected`，不得以演示结果代替个人使用结论。
